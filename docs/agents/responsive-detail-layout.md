# PVX 资料详情页响应式维护规则

## 1. 文档职责

本文记录可跨书籍、剑侠录、伙伴等资料型详情页复用的响应式实现约束。单个页面的业务字段、固定尺寸和专属断点必须放在 `docs/project` 或 `docs/design`，不要写入本文。

## 2. 使用真实可用宽度设计

- 页面带侧栏时，组件可用宽度小于浏览器视口。
- 不能只用视口断点推断某个固定列一定放得下。
- 固定图片列、操作列和 Grid Gap 的总和必须小于内容列实际宽度。
- 中间尺寸应允许视觉列收缩、换行或降级为下一行，不能依赖 `overflow: hidden` 掩盖溢出。
- 条件允许时优先使用 Container Query；继续使用媒体查询时，需要覆盖“视口较宽但内容列较窄”的场景。

## 3. 图片稳定与防变形

- 有天然构图比例的插画、章节头图和封面不得使用拉伸填充。
- 桌面需要稳定布局时，可以固定显示窗口并提前占位；素材仍按自身比例渲染。
- 裁切应发生在明确的显示窗口中，并通过 `object-position` 或内部宽度保护主体构图。
- 手机需要铺满宽度时优先使用 `width: 100%; height: auto;`，不要同时写与素材冲突的强制 `aspect-ratio`。
- 骨架、空占位和真实图片必须遵守同一列宽规则，避免加载前后布局跳动。

## 4. 多行控件的对齐

- “左侧视觉主体 + 中间可换行控件 + 右侧操作区”布局应分别定义：
  - 模块整体相对视觉主体的垂直位置；
  - 中间控件与右侧操作的顶部基线；
  - 控件换行方向。
- `align-items: center` 只能解决整体居中，不能自动保证两个不同高度模块的首行顶部对齐。
- 可通过相同模块高度、内部顶部排列或明确 Grid 行实现首行对齐。
- `flex-wrap` 场景应设置 `align-content: flex-start`，确保新行向下增长。

## 5. Sticky 与结构边界

- Sticky 元素不能被需要滚过的短父容器限制。
- 祖先的 `overflow: hidden/auto` 会改变 Sticky 的滚动和裁切边界，实施前必须检查完整祖先链。
- 当桌面控件必须参与卡片 Grid、手机控件又必须跨正文 Sticky 时，可以保留两份展示结构。
- 双结构只能共享同一份业务数据、选中状态和事件方法；不得形成两套请求或状态。
- 通过明确的 `--desktop`、`--mobile` 变体互斥显示，并验证断点边界不会同时出现或同时隐藏。
- Sticky 顶部偏移必须避开公共 Header，背景需要足够不透明，圆角和边框与相邻 Surface 协调。

## 6. 终端降级

- 桌面操作区不能在窄屏被简单压缩到文字或按钮裁切。
- 根据业务优先级选择换行、整行展示或隐藏；最终规则写入对应项目文档。
- 隐藏辅助操作时，必须同时移除其布局占位。
- 小程序、App WebView 和普通手机 Web 的显示规则可能不同，不得只用屏幕宽度替代终端判断。

## 7. 最低验证

- 图片加载前后无宽度跳动；
- 图片在桌面、Pad、手机均无拉伸；
- 可换行控件首行对齐且只向下增长；
- 带侧栏的 Pad 尺寸没有横向裁切；
- Sticky 元素能持续覆盖正文滚动区；
- 横向滚动控件可触摸滚动且不制造页面级横向滚动；
- 桌面和手机双结构的选中态与请求状态完全一致。
