# 资历宝典现代化改造准备

## 1. 文档定位

本文记录 `/pvx/codex/achievement` 现代化改造前的代码盘点、业务保护边界、建议拆分和验收基线。

视觉与响应式实现继续以以下文档为准，不在本文重复定义：

- `docs/design/pvx-visual-style-guide.md`
- `docs/design/responsive-adaptation-guide.md`
- `docs/agents/pvx-index-style-migration.md`

## 2. 当前模块范围

资历宝典共用 `src/views/wiki/index.vue` 外壳，主要路由为：

| 路由 | 当前页面 |
| --- | --- |
| `/codex/achievement/overview` | `src/views/wiki/overview.vue` |
| `/codex/achievement/compare` | `src/views/wiki/compare.vue` 统一承载 `compare/pc.vue` 响应式 Web 页面 |
| `/codex/achievement/leap` | `src/views/wiki/leap.vue` 统一承载 `leap/pc.vue` 响应式 Web 页面 |

目录、列表、对比目录和对比成就等旧宿主专用子路由已经下线，不属于当前 Web 路由。

公共业务依赖主要包括：

- `src/service/achievement.js`：菜单、点数、角色成就、成就列表、搜索和地图等接口；
- `src/service/team.js`：用户角色；
- `src/service/wiki.js`：亲友和亲友角色；
- Vuex 中的 `role`、`achievements`、`achievementsVirtual`、`viewAchievementsName` 等状态；
- `@jx3box/jx3box-common` 的角色、图标和成就详情链接能力；
- Element Plus 表格、下拉、级联、弹窗和加载状态；
- `xlsx`：亲友对比导出。

## 3. 现状判断

### 3.1 外壳

当前 Web 外壳是固定高度的深色全屏画面：

- 主区 `min-width: 1260px`、`height: calc(100vh - 60px)`；
- 内容区固定 `960px`，侧栏固定 `180px`；
- 主区自身横向滚动，页脚仍在文档流中；
- 主区使用 `https://cdn.jx3box.com/design/pvx/overview-bg.png` 与现有深色渐变共同构成资历宝典的国风背景；
- 移动判断依赖 User-Agent，而不是响应式 Web 断点；
- 样式由 `.m-achievement-*` 等宽泛旧类开启，没有现代模块专有根节点。

当前需要改造的是固定宽度、滚动方式、内容层级、响应式和样式隔离。现有国风背景属于资历宝典的核心视觉资产，不属于需要替换的旧样式。

### 3.2 完成进度

`src/views/wiki/overview.vue` 当前约 1300 行，单文件同时承担：

- 登录校验、用户资料和角色加载；
- 角色切换与最近角色记忆；
- 菜单、成就点数和角色完成数据请求；
- 分类树递归聚合、总资历和完成率计算；
- 分类下钻、返回和末级成就表格；
- 桌面与 User-Agent 移动布局；
- 页面绝大部分样式。

主要风险：

- 未登录时先弹确认框，主体因 `currentRole` 为空完全不渲染，用户无法先理解页面用途；
- `getRenderList` 由多个 watcher 和请求阶段触发，改造时容易引入重复计算或异步覆盖；
- 分类下钻依赖 `list_bak`、`name_bak` 和 Vuex 名称状态，返回语义不能只靠视觉重排替换；
- `getCurrentProgress(own, all)` 未单独防护 `all = 0`；
- 页面通过固定高度和内部滚动承载内容，改为自然页面滚动时需要重新处理返回、Sticky 和表格高度；
- 大量界面文案仍为简体中文硬编码，现有 `pages.wiki.*` 路由元信息键也未形成资历宝典完整四语言界面词条。

### 3.3 亲友对比与渡劫方案

亲友对比已经具备较完整业务能力，但仍是独立旧布局：

- 分类菜单、搜索、地图、完成状态筛选、多角色横向表格；
- 自身/亲友角色添加、移除；
- 当前结果导出 Excel；
- 表格宽度按角色数动态扩展。

渡劫方案包含角色切换、方案列表、自定义方案、方案详情和路由查询参数恢复等流程。改造前两页分别维护 PC/Mobile 组件并使用 User-Agent 判断；2026-07-26 已将普通 Web 收敛为同一现代响应式页面，旧移动组件不再作为普通手机浏览器入口。

因此“资历宝典”应视为一个多阶段模块工程，不能把总览改造后的局部样式直接覆盖到对比和渡劫。

## 4. 风格来源与可复用能力

本轮风格基线来自：

1. `tmp/index` 所形成的全站信息密度、卡片化内容和导航层级；
2. 已验收的 Face / Body 响应式列表、详情和角色相关操作；
3. 奇遇大全的全宽 Web 页面、Sticky 工具栏、分类卡片和空状态；
4. 奇遇珍卷的艺术背景保留方式，以及登录、无角色、加载等显式状态；
5. 当前公共设计组件和设计令牌。

### 4.1 背景视觉硬约束

资历宝典现代化改造必须保留当前整体背景图片及其国风视觉：

- 不替换、重绘、裁改或重新着色 `overview-bg.png`；
- 不通过滤镜、模糊、强遮罩或大面积不透明浅色背景改变原图的整体观感；
- 保留背景当前的构图方向、深色基调和金棕色氛围；
- 页面新增颜色、边框、图标和交互状态必须从现有背景的黑、棕、金、米白色系中协调提取；
- 公共 PVX 的靛蓝主色和浅灰页面底不能机械覆盖到该模块，只能在不破坏背景风格时选择性使用；
- 页面在桌面、平板和手机尺寸变化后，都要检查背景主体没有被内容布局异常裁切或完全遮挡。

参考奇遇珍卷 `treasure-shell-theme.less` 的实现原则：

- `PvxPageShell` 继续提供页面结构、安全边距和响应式承载；
- 模块专有根节点重新声明原有艺术背景，覆盖公共页面壳的默认底色；
- 画面本体保持透明，现代化只发生在工具栏、状态卡、交互控件和滚动容器；
- 艺术内容与现代外围组件各自保持独立作用域。

资历宝典应采用相同策略：保留原背景作为完整页面基底，在其上使用与背景协调的半透明深色、暖色浅面板或米白内容表面，不把页面改造成通用浅色后台风格。

### 4.2 可复用能力

优先复用：

- `PvxPageShell`：页面结构、安全边距和基础宽度；其默认浅色背景必须由资历宝典专有根节点覆盖；
- `PvxSurface`：角色概览、分类区、列表区和提示区；
- `PvxSectionHeader`：页面及分区标题；
- `PvxToolbar`：角色切换、筛选、搜索和主要操作；
- `PvxActionButton`：登录、绑定角色、返回和方案操作；
- `PvxEmptyState`：未登录、无角色、空分类、无搜索结果和加载失败；
- `src/assets/css/design-system/_tokens.less` 与 `_mixins.less`。

资历宝典信息密度高，Web 端可像奇遇大全和考试大全一样在模块根节点内解除 `PvxPageShell` 的 `1440px` 上限，但仍必须保留统一安全边距，不修改公共组件默认值。

## 5. 建议目标结构

### 5.1 模块外壳

- `index.vue` 统一使用公共头部、`Nav_v5`、`Main` 和页脚结构；
- 由路由显式开启 `.c-pvx-modern-achievement-*` 根类；
- 现有 `overview-bg.png` 继续作为模块整体背景，不切换为通用 `@pvx-page-bg`；
- Web 页面使用自然文档流，不再依赖整页固定高度和主区横向滚动；
- 左侧国风侧栏可重组为内容内的分段导航或 Sticky 导航卡，但其新版外观必须继续服从背景的国风色调，并保留“完成进度 / 亲友对比 / 渡劫方案”信息架构；
- 桌面、平板和手机统一使用当前 Web 路由，主题差异只按模块根节点和响应式断点处理。

### 5.2 完成进度页面

建议拆成四层：

1. 页面 Hero：标题、当前角色、总资历、总进度和同步说明；
2. 分类概览：响应式分类卡片，展示完成数、资历点与完成率；
3. 分类面包屑/返回：明确当前层级，不再只依赖侧栏名称变化；
4. 末级成就列表：桌面表格，窄屏改为信息卡或受控局部滚动。

业务逻辑建议先从大文件抽出纯函数或 mixin/composable：

- 分类树递归汇总；
- 完成成就集合标准化；
- 总点数与分类点数计算；
- 进度值归一化；
- 分类下钻路径和返回栈。

只有确认在对比或专用端也稳定复用后，才提升为跨页面公共能力。

### 5.3 登录与角色状态

首屏必须显式区分：

- 未登录；
- 已登录但无绑定角色；
- 角色列表加载中/失败；
- 成就数据加载中/失败；
- 已选择角色且有同步数据；
- 角色存在但未同步或成就为空。

不建议继续以进入页面立即弹确认框作为唯一未登录体验。登录和角色绑定仍使用原入口，不改变权限与接口语义。

## 6. 分阶段实施建议

### 阶段 A：公共外壳与完成进度

- 建立 Web 专有现代根节点和主题文件；
- 在专有根节点中原样承接现有国风背景图片和综合色调；
- 改造模块导航、页面壳和完成进度首屏；
- 保留全部接口、角色同步、分类树和详情跳转；
- 补齐加载、未登录、无角色、空数据和失败状态；
- 完成响应式与四语言界面文案。

### 阶段 B：分类下钻与成就列表

- 使用明确的层级导航替代隐式备份状态；
- 重组末级成就列表，保留奖励 Tooltip、完成状态和新窗口详情；
- 验证大分类、零点数、长名称和异常奖励数据。

### 阶段 C：亲友对比

- 将筛选、搜索、地图和导出整合进统一工具层；
- 保留多角色动态列与横向滚动，但只允许表格容器滚动；
- 重组添加角色弹窗、空角色和无结果状态；
- 验证自身/亲友、角色移除、筛选组合与导出内容。

### 阶段 D：渡劫方案

- 统一方案列表、创建表单和详情结构；
- 保留方案计算、路由查询参数、角色切换与所有写操作；
- 对新增、编辑、删除等有副作用的行为单独回归。

### 阶段 E：多视口与边界复核

- 覆盖桌面、平板和手机 Web 的布局与交互；
- 确认旧宿主专用深链不再加载已下线页面；
- 验证模块根节点和公共逻辑抽取没有影响其他 PVX 页面。

## 7. 必须保护的业务行为

- 路由名称、路径、查询参数和现有跳转语义；
- 正式服/怀旧服 `client` 参数；
- 用户角色、最近角色和角色成就同步；
- 菜单与成就点数的统计口径；
- 分类树中数组成就、系列成就和去重逻辑；
- 成就详情外链、奖励物品 Tooltip；
- 亲友关系、亲友角色和多角色对比；
- Excel 导出字段与当前筛选结果；
- 渡劫方案的创建、读取、详情和修改流程；

必须保护的视觉资产：

- 资历宝典整体 `overview-bg.png`；
- 当前背景的深色渐变、构图方向和国风氛围；
- 分类、资历、头像和侧栏中的业务识别性美术资源。

现代化允许调整这些资产外围的布局、尺寸承载、信息层级和交互反馈，但不得擅自替换或修改资产本身。

## 8. 验收矩阵

### 数据状态

- 未登录、无角色、单角色、多角色；
- 已同步、未同步、空成就、接口失败；
- 总览、一级分类、末级分类、返回；
- 零点数、超长分类名、缺图标、缺奖励；
- 亲友为空、亲友无角色、添加/移除多个角色；
- 渡劫方案为空、有方案、详情和表单。

### 视口

- `1920 × 1080`
- `1440 × 900`
- `1280 × 800`
- `1024 × 700`
- `768 × 1024`
- `390 × 844`
- `320 × 568`

重点检查页面级横向溢出、Sticky 遮挡、表格局部滚动、长文本、弹窗宽度、页脚位置和触控区域。

每个视口还必须单独进行背景回归：

- 背景图片仍清晰可辨且没有被大面积浅色表面遮住；
- 主要构图没有因容器高度、`background-size` 或定位变化出现异常裁切；
- 内容文字与背景对比度足够；
- 半透明表面、边框、阴影和强调色与原背景协调；
- 页面向下延伸时背景衔接自然，不出现突兀的通用浅灰底。

### 语言

- `zh-CN`
- `zh-TW`
- `en-US`
- `vi`

游戏成就名、角色名、服务器名和接口内容保持源文；只翻译前端维护的界面文案。

### 自动检查

```bash
npm run lint
npm run verify:legacy-js
npm run build:dev
git diff --check
```

当前仓库没有资历宝典专项自动测试。实施时至少应补充纯数据聚合函数测试，避免视觉重构改变资历统计口径。

## 9. 当前准备结论

推荐先以普通 Web 的 `/overview` 为第一交付单元，同时把 Web 公共外壳设计成能承载后续 `/compare` 与 `/leap` 的结构。视觉上采用奇遇珍卷的“原艺术背景保留、现代外围组件叠加”策略，不迁移成通用浅色页面。第一阶段不应直接改造专用端，也不应一次性重写全部业务逻辑；先通过纯数据层保护和状态拆分稳定统计口径，再进行结构与视觉迁移。

2026-07-25 已完成普通 Web `/overview` 第一版：

- 原 `overview-bg.png`、深色渐变、背景构图方向和国风基调保持不变；
- Web 外壳改为自然高度、弹性内容区和响应式顶部/侧边导航；
- 新增深色角色总览、暖米色分类卡片、分类下钻标题和现代成就表格；
- 未登录、无角色、加载失败和重试改为页面内显式状态，不再进入页面立即弹出登录确认框；
- 新增界面文案已覆盖简体中文、繁体中文、英文和越南文；
- 该日亲友对比和渡劫方案尚未改造；两者已在下一阶段完成响应式收敛。

本轮已通过目标文件 ESLint、`npm run verify:legacy-js`、`npm run build:dev` 和 `git diff --check`。浏览器回归覆盖 1280px 桌面与 390px 手机未登录状态，页面无横向溢出且控制台无新增错误或警告；登录态角色切换、分类下钻与成就表格等待用户使用真实账号验收。
