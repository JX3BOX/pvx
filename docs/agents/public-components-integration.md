# PVX 公共组件接入规则

## 1. 文档职责

本文只记录 PVX 消费 `@jx3box/*` 公共组件时可跨页面复用的实现边界。

具体依赖版本以 `package.json` 和 lockfile 为准；单个页面的数据、布局与回归结果应分别记录在 `docs/project` 和 `docs/design`，不在本文维护版本快照或阶段流水。

接入同时遵循：

- `docs/design/pvx-visual-style-guide.md`
- `docs/design/responsive-adaptation-guide.md`
- `docs/common/i18n-development-guide.md`

## 2. 宿主与公共组件的职责

公共组件负责：

- 自身字段、内部结构和交互状态；
- 组件内部固定界面文案与可访问性；
- 组件支持的主题、variant 和响应模式；
- 内部加载、失败和空状态；
- 组件文档已经声明的尺寸响应能力。

PVX 页面负责：

- 页面 Grid、模块顺序、页面安全边距和区块间距；
- 公共组件所在容器的可用宽度和统一 WebView 下的响应式排列；
- 页面业务数据、权限和路由；
- 业务按钮的页面级位置；
- 公共组件没有覆盖的页面组合状态。

页面不得复制公共组件的完整内部主题，也不得用深层选择器重新实现组件已经提供的能力。

## 3. Variant 与使用场景隔离

- 普通 Web 的 WikiPanel、WikiRevisions、WikiComments 使用公共组件支持的 `surface` variant。
- 机器人、抓图等非页面输出不能因普通 Web 接入新 variant 被动变化。
- 机器人场景继续使用约定的默认 variant，除非对应协议明确升级。
- 新主题必须从页面专有根节点或显式 variant 开始生效，不能覆盖同组件的全部实例。
- 普通 Web 与机器人等协议输出共享组件时，先确认结构和文案协议，再决定是否复用同一主题。

## 4. i18n 边界

- 公共组件固定界面文案由公共库命名空间维护。
- PVX 复用宿主 i18n 实例合并公共库词条，不创建第二套语言状态。
- 页面标题、按钮、筛选、空状态等 PVX 固定 UI 使用项目 i18n。
- 用户正文、游戏名称、地图名、NPC 名、服务器名和接口内容继续使用源数据，不能由公共组件猜测翻译。
- 机器人协议关键词即使显示在多语言界面中，也必须保持接口要求的原值。

## 5. 公共 Wiki 组件

- `PvxUser` 负责向 WikiPanel、WikiRevisions 和 WikiComments 传递页面约定的 variant。
- 页面只维护百科社区区块的外框、Grid、顺序和间距。
- 不覆盖 panel head/body/title/actions、评论正文和修订列表等内部结构。
- 公共组件升级后，优先删除已由公共库承担的本地覆盖，而不是继续叠加补丁。
- 若公共组件能力不足，应先评估公共库 API 或 CSS Variable，不直接依赖内部 class。

## 6. Facedat / Bodydat

- Facedat/Bodydat 的字段、参数组、贴花结构、Slider 和组件主题由 `@jx3box/jx3box-facedat` 维护。
- PVX 不保存该公共库内部主题的完整副本。
- 页面只处理预览区最小高度、详情模块间距、页面宽度和终端顺序。
- 公共库新增响应式能力后，应清理页面中对应的 Tab、列表、参数和滚动覆盖。

## 7. 地图组件

- 优先使用地图库公开的 `focus`、`overview`、`responsive` 等模式。
- 容器变化优先交给公共组件的 `ResizeObserver` 或公开 resize API。
- 页面不得固定覆盖地图内部画布宽高来制造表面适配。
- 地图 ID、点位、NPC 和业务说明由页面传入，公共组件负责渲染和固定 UI。
- 地图加载、失败、重试、子地图切换等固定提示由公共库 i18n 维护。
- 页面必须保留地图业务内容，不能因为平板或手机适配困难直接隐藏。

## 8. 样式覆盖原则

- 优先使用公开 props、slots、variant 和 CSS Variable。
- 页面覆盖必须带模块根节点，避免影响其他消费者。
- 只覆盖宿主职责，例如容器宽度、区块间距和模块排列。
- 不使用 `!important` 对抗公共组件内部主题，除非为已确认的第三方兼容问题且附有说明。
- 升级公共库后先搜索并清理重复覆盖，再添加新的兼容代码。

## 9. 返回顶部组件

- 普通 Web 的列表与详情路由统一使用项目公共 `PvxBacktop`，颜色遵循 PVX 靛蓝主题。
- 组件应挂在可覆盖整组子路由的模块根容器，不应在列表、详情或 Tab 子页面重复接入。
- 模块根容器已经接入后，应删除子页面中的 `el-backtop` 或重复 `PvxBacktop`，避免同屏出现多个按钮和重复监听滚动事件。
- 机器人等非页面模板如有独立滚动容器，继续按输出协议处理，不机械复用普通 Web 挂载位置。
- 当前根级接入范围包括奇遇、体型、脸型、宠物、家具、价格走势、资历宝典等 Wiki 页面，以及原本已接入的坐骑、科举、书籍、声望、家园、红尘侠影和剑侠录。

## 10. 升级与回归

公共依赖升级后至少检查：

- `package.json` 与 lockfile 版本一致；
- 普通 Web 与机器人等输出协议的 variant 没有串用；
- 四语言固定 UI 正常，游戏源数据没有被错误翻译；
- 英文、越南文长文本没有撑宽页面；
- 公共组件内部没有被本地旧样式重复覆盖；
- 地图和数据查看器在桌面、Pad、手机容器内正确响应；
- `git diff --check`、目标文件 lint、旧版 JavaScript 检查和必要构建通过。

具体页面的回归矩阵应写入对应 `docs/project/*.md`，本文不维护一次性的通过记录。
