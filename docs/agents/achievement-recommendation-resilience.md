# 后端推荐预览的数据容错

适用于 `AchievementLeapRecommendation.vue` 中的主页推荐结果；不改变后端候选资格；草稿初始化保留后端顺序，先确定入选成员，再组织展示。

## 详情与难度

- 成就详情和难度按当前页签的连续列表独立加载、缓存和重试，每类请求按 240 项顺序分批，跨原分组合并。详情逐批展示已加载的连续前缀，后续失败不得隐藏已显示的条目；重试只补缺失项。
- 详情成功即可展示、调整清单；难度较慢或失败不得阻塞列表和基于有效资历数据的方案创建。
- 难度失败显示非阻断提示，重试只请求尚未成功的难度数据，不重复请求详情；详情失败仍显示详情重试入口。
- 难度接口成功返回的未配置值 `null` 不属于请求失败，也不得伪造为 0 分。
- 推荐更换后清空两类缓存和请求状态，旧请求不得回写新推荐。

## 入选资历校验

- 初始推荐按草稿当前顺序累加目录资历，达到目标后停止；未入选候选缺资历不阻止创建。手动清单则校验全部入选项。
- 达到目标前遇到缺失、负数或非数值资历时阻止创建，并提示对应成就 ID；不得当作 0，也不得自动跳过。
- 明确的数值 0 有效；初始清单随目标计算，手动调整后固定成员，所有手动入选项都校验点数。
- 目录数据仍是入选资历的来源，不依赖详情加载进度。

## 推荐清单排序

适用于主页的“已入选清单”。默认规则为：**整体遵循后端返回顺序，遇到秘境成就时，在其首次出现的位置聚拢同地图的其他已入选秘境成就。**

1. 先按后端返回的分组顺序及组内成就顺序展开候选，累计资历到目标，确定实际入选成员；再对这些成员进行展示排序。
2. 界面始终使用一个连续列表，不拆分“副本成就”和“其他成就”分区，也不把所有副本统一排到最前面。
3. 按原顺序遍历入选成员。遇到某地图的第一条秘境成就时，把该地图其余已入选秘境成就按原相对顺序接到它后面；后续遍历到已经聚拢的条目时跳过，避免重复展示。
4. 非秘境成就保持彼此的原相对顺序，即使它们与秘境成就在同一地图，也不参与聚拢。不同副本地图按首次遇到的位置排列，不按地图名称或 ID 大小排序。
5. 聚拢只调整顺序，不从候选池额外拉入成就，不改变入选数量、入选资历或自动补入的选择依据。

示例中，A1、A2 是地图 A 的秘境成就，B1、B2 是地图 B 的秘境成就，“其他”均为非秘境成就：

```text
后端顺序：其他1 → A1 → 其他2 → B1 → A2 → 其他3 → B2
展示顺序：其他1 → A1 → A2 → 其他2 → B1 → B2 → 其他3
```

识别、筛选和调整遵循以下边界：

- 秘境身份由目录中的“秘境”分类 ID 判断，不能根据 `scene` 分组或名称关键字推断。同地图秘境成就可以跨成本档、跨子分类聚拢；`scene/map` ID 命名空间分离，实际不同地图 ID 不合并。手动增加项使用详情的原始 `SceneID/dwMapID` 定位，缺失地图不猜测。
- 搜索、地图和分类筛选在完整聚拢顺序上进行，隐藏首条秘境成就不得改变该地图剩余条目的相对位置。候选弹框保持草稿顺序，待开放活动保持原展示且不参与聚拢。
- 整个列表允许手动拖动。第一次拖动后，以 `presentationOrderIds` 保留显式顺序，不用自动聚拢覆盖用户调整；之后新增或自动补入的条目追加到手动顺序末尾。撤销调整或重新生成时，恢复后端顺序、重新确定初始入选并应用默认聚拢。
- 保存使用完整展示顺序，通过 `includedIds` 携带全部入选成员，不因聚拢后提前达到目标而再次截断。详情尚未加载时，点击保存只为缺失分类／地图的入选项补轻量索引，不等待难度或请求完整候选池；准备过程复用保存中状态及上下文校验，失败允许重试，过期响应不得写入新草稿。

实现入口：`src/utils/achievementRecommendation.js` 的 `arrangeAchievementRecommendationItems`；行为验证：`scripts/test-achievement-recommendation.js`。

## 查看范围与目标汇总

- 主列表只展示已入选；摘要右侧“查看候选（数量）”打开弹框，只包含尚未入选的成就。两份名单互斥，共用筛选条件与全局筛选选项，详情／难度／标签共享缓存、独立加载；待开放活动仍独立展示且不参与入选。
- 摘要“增加成就”与方案编辑添加入口共用完整未完成普通可见正资历目录。全量轻量索引同时加载公共标签，以 `tag_type=mount` 的 `tag_value.operator/values` 判断门派可完成性，接口规则优先，无门派规则才用原本地回退；目录过滤后再搜索、计数与分页，选入时复核。标签读取失败不放行候选并提供重试；分页复用标签，仅详情和难度读取当前 15 项，不补取隐藏成就详情。打开即可浏览，无关键词也可添加，已入选项显示禁用标记。难度失败允许继续添加并可重试，旧角色／客户端及旧页请求不得回写当前结果。
- 完整目录选入先确认单项：确认之前不更改草稿；现有候选复用原行与原分组，推荐池外条目以独立 `manual:<id>` 分组追加，手动分组仅表示来源，不表示地图或评分。显示为“手动增加”；重复／已完成／非法点数不能添加。原有入选全部保留，额外项目进入 `includedIds`、资历汇总和保存清单；删除回到候选，撤销与重新生成清除本次新增。全量筛选索引异步返回时不得覆盖后加入的手动索引。
- 查看范围和搜索筛选不参与入选计算，保存始终使用实际入选清单，不能把整个候选池或当前搜索结果作为方案内容。
- 初次推荐按后端顺序取达到目标的最短前缀；手动选入额外保留，排序不改变成员。候选选入保留原有入选并额外添加；已入选删除回到候选，预计资历不足目标时保留其余已入选，并从完整候选池按草稿顺序补足；候选删除不影响已入选。排序和目标变更不改手动清单成员，只更新顺序／目标差额。重新生成或撤销调整才恢复按目标自动选择。
- 选入、删除必须二次确认，默认单个，可选相关组，并展示影响名单与数量。整组操作限定当前名单；关系按后端原始组的地点聚合，同地点不同成本档合并、scene/map ID 分离，手动排序不改分组关系。关闭确认不发生修改，新推荐／撤销使旧确认失效。
- 自动补入只在已入选移除导致不足目标时执行，筛选条件只影响展示，不限制补入范围。已移除项记入本次草稿的自动补入排除集合，避免立即或后续自动选回；手动选入可恢复，撤销／重新生成清空该集合。候选不足时保留实际差额，必需补入项缺失点数时阻止保存，不静默跳过。
- 轻量筛选索引只决定匹配 ID，不能把索引中的空图标、空描述、默认点数合并进展示条目；列表字段始终来自完整详情与草稿元数据。
- 保存端必须保留所有实际入选项，包括初始入选和手动增加项，不得因展示重排而按目标再次截断；必需点数缺失时阻止单个／整组加入和保存，整组操作不允许部分成功。
- 预计资历等于接口角色当前资历加上入选资历；明确展示目标、仍差多少或超出多少。未达目标但数据完整的方案仍可保存，不新增达标门槛。
- 必需资历缺失时不展示可确定的预计资历、缺口或达标状态；待开放活动不受“只看已入选”影响。
- 推荐结果随主页自然滚动，列表不设置独立滚动容器；标题、入选与目标汇总、查看候选、增加成就、重新生成和撤销调整紧凑吸附于顶部；清单标题、活动切换和筛选后数量随正文滚动。筛选或切换查看范围后按吸附栏实际高度定位首条结果，避免遮挡；不改动草稿与入选计算。
- 开关方案列表抽屉、查看方案详情后返回主页保留清单与共享筛选条件；撤销调整或生成新推荐时关闭候选及确认弹框，恢复初始入选。
- 三个操作使用带图标的文字按钮和提示：重置偏好保留方案名称和目标资历，仅在点击时已有推荐结果才自动重新生成；未开始或当前没有结果时只恢复偏好。重新生成重新请求接口并替换结果和调整；撤销调整仅在有推荐结果时展示，恢复后端顺序与初始入选，再仅聚拢同地图秘境成就。吸附栏不展示重复的保存范围说明，额外选入和移除后的自动补入规则保留在正文。
- 重置后等待偏好更新再复用生成入口；加载中或控件禁用时拒绝重置，缺少可用角色时只重置偏好、不发请求。重新生成不传随机参数，也不在本地随机换一批，服务端结果是否相同由请求参数及后端数据和算法决定。

## 同步信息与排除说明

- `role.snapshot_updated_at` 和活动 `next_start_at` 按 UTC+8 展示；缺失或非法时间显示未知，不推断“没有快照”或“全部未完成”。
- 旧同步记录提示只遵循 `role.snapshot_stale`，前端不额外定义有效期阈值。
- “查看同步指引”新页打开个人中心 `/dashboard/role/sync`，保留当前草稿；刷新推荐只重新请求推荐，不代替游戏数据同步。
- `excluded_summary` 原样分原因展示有效正整数计数，未知原因保留服务端键名；不求和为去重总数，也不据此补删候选。

## 公开标签与待开放活动

- 推荐条目标签按当前页签的连续列表独立分批请求 `fetchAchievementWorkbenchTags`；失败可单独重试，不影响详情、难度、入选或保存。成功返回无标签按空数组缓存。
- 仅展示公开标签名称、描述；门派标签稳定前置，去掉普通/常规成就标签，保留中立角色的原阵营限制提示。标签不参与后端推荐结果的二次资格过滤或排序。
- 首次进入待开放活动页签时通过公开标签详情接口补名称，最多三个请求并发；成功无名称回退活动标签编号，失败提供重试。
- 标签、活动名请求跟随推荐上下文失效；晚到的旧结果不得污染新角色/新推荐。
- 待开放活动仍只供预览，不混入当前推荐或保存清单。

统一验证命令：`npm run test:achievement`。单项排查仍可直接运行对应文件，例如 `node scripts/test-achievement-recommendation.js`。

## 编辑与创建的状态隔离

- 页面存在编辑中的方案或复制后的本地清单时，主页推荐工作区保持挂载但隐藏，方法调用不得发起推荐。进入编辑前保留推荐基础表单，编辑使用新表单；放弃或保存编辑时清除编辑对象、清单和保存／添加弹框，并恢复原推荐表单，不清空推荐结果、入选和筛选。切换角色或客户端清除旧表单备份。
- 推荐方案创建成功后，进入新详情前统一退出残留编辑状态，并使旧编辑加载请求失效；保存本地方案成功也使用同一清理逻辑。返回主页不再恢复旧编辑清单，保留原推荐名称和目标资历。创建失败保留草稿，已过期的创建响应不得清除新上下文的编辑状态。
