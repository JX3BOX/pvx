# 资历宝典页面设计规范

> 最后更新：2026-09-05。本文记录当前确认的最终交互，不保留被后续反馈替换的中间方案。

## 1. 适用范围

本文描述普通 Web 资历宝典 `/achievements`、`/achievements/compare`、`/achievements/leap` 的新版信息结构、视觉语言和响应式规则。业务状态、接口边界和实施阶段见
[`../project/achievement.md`](../project/achievement.md)，统一字段协议见
[`../agents/achievement-workbench-data-contract.md`](../agents/achievement-workbench-data-contract.md)。

新版以“魔盒成就百科”交互原型及确认稿图 1 为功能与结构参考。旧资历宝典代码、侧栏和深色国风背景不再是保护对象。

## 2. 页面骨架

三页必须共享同一个工作台外壳：

1. 站点公共导航与 Header；
2. 暖纸色工作台容器；
3. “完成进度 / 亲友对比 / 渡劫方案”顶部页签；
4. 独立的“资历宝典使用指南”入口；
5. 当前路由的业务内容；
6. 公共返回顶部与 Footer。

模块页签在所有 Web 断点保持顶部布局，不再切换为桌面侧栏。页签支持键盘焦点、明确激活态和移动端横向滚动；使用指南在窄屏可收敛为图标按钮，但必须保留可访问名称。

## 3. 视觉语言

-   页面底采用低对比暖纸色，可使用细微纤维纹理和青灰色晕染，不使用大面积深色游戏背景；
-   主内容表面以米白、浅暖灰为主，边框低对比、阴影克制；
-   主强调色使用黛青/青灰，第二强调色使用暖金；
-   状态色仅用于完成、警告、绝版、隐藏和错误等语义，不作为大面积装饰；
-   数字使用等宽或制表数字特性，进度、点数、成本等级应易于纵向比较；
-   允许原有游戏图标、角色头像和业务美术继续出现在内容区，但不决定新版外壳配色。

## 4. 三页信息结构

三页的难度展示共同遵守以下规则：维度名称、顺序和显示项只取公共维度定义；接口不可用时才回退内置五维。综合难度（`overall`）始终以支持小数填充的五颗星表示，星级后显示一位小数（如 `0.5`），不使用“0星”等整数档位文案覆盖真实分数。其他维度配置了 `score_labels` 时按区间展示文案，下限包含、下一档下限不包含，按原始分数匹配，不四舍五入后分档；悬浮提示保留具体分数。没有匹配文案时回退为相同的星级展示。星级不显示可见的 `x/5`；供辅助技术读取的 `aria-label` 可以保留 `2.5/5`。星级模式下 `0` 显示为空星和 `0.0`，只有 `null` 或非法值显示“—”。所有成就入口及亲友对比导出均隐藏同步完成率和角色样本计数；角色自身进度、方案完成率保留。成就名称下显示真实描述，长文案允许换行，缺少描述不显示空占位。

成就元信息按实际数据存在性展示：没有地图名时不渲染地图块，没有奖励引用时不渲染奖励块。常规成就不显示“常规成就”档位 tag，五甲档位 tag 保留；业务标签中的门派标签排在节日、活动、阵营及其他标签之前。分类名、标签、门派限制和备注都不能用占位文案制造业务含义。

### 4.1 完成进度

按以下顺序实现：

1. 当前角色、排序和筛选；
2. 总资历、总完成率、已完成成就数；
3. 常规、五甲、隐藏、绝版等分类总览；点击常规或五甲卡片直接修改主页面成就列表的档位筛选，隐藏卡片跳转 Wiki 的隐藏成就维护文章，绝版卡仅展示统计；
4. 主页面的成就列表顶部提供档位、完成状态、地图、排序、搜索和重置；档位仅包含常规、五甲两项并默认常规，排序默认保留原始目录顺序，同时提供未完成优先等排序选项；重置恢复常规档位、全部状态、全部地图、默认排序、空关键词和全部分类；分类由左侧分类进度列表直接控制，不重复展示分类下拉；右侧列表标题不追加“成就”，一级分类直接显示一级名称，二级分类显示“一级 / 二级”，选择全部时显示“全部”；
5. 分类进度恢复旧版一级分类图标；桌面展开一级分类后采用左侧一级目录、右侧二级目录的主从双栏，左栏仅保留图标、名称、完成率和进度条，窄屏降级为上下布局；一级和二级分类都可联动筛选全部成就列表；
6. 难度维度按公共定义动态展示；默认只读取当前可见页，用户主动选择某一维度排序时才补齐当前候选集，补数失败则保留原排序并提示。

成就列表继续保留奖励信息。当前页存在奖励引用时展示奖励字段：物品奖励加载图标、详情悬浮卡片和物品链接；无法解析的其他奖励使用通用奖励标识，加载失败显示不可用提示。没有奖励引用的记录不渲染奖励块。奖励物品按当前页批量读取并复用会话缓存。

总览与分类总览采用紧凑高度，并允许整体折叠。折叠入口位于角色栏右侧；折叠后保留角色切换、同步状态和展开入口，不影响当前角色、分类或成就筛选状态。分类与列表顶部对齐、随内容自然增高，整页纵向滚动，每页 15 项；折叠态不再限制工作区高度。展开二级分类后恢复一级、二级主从双栏。

主页面的分类筛选和分类进度沿用旧版目录口径：仅展示包含 `general=1` 常规成就的顶层分类，排名、江湖百态等仅包含其他档位成就的辅助目录不进入主分类。未展开二级分类时，一级分类只使用单列，不为了填满宽度拆成两列；目录随内容展开，不设置内部纵向滚动。

常规和五甲成就不设置独立二级路由；两张分类总览卡片与主列表档位下拉使用同一个 `filters.tier` 状态，点击卡片后 URL 不变，并立即刷新下方列表。隐藏成就不参与档位筛选，分类总览卡片跳转到 Wiki 隐藏成就文章；绝版成就不参与档位筛选，也不提供点击入口。

### 4.2 亲友对比

-   当前角色沿用完成进度页最近选择的本人角色并固定为首个基准角色，不提供移除入口，父页面删除逻辑也必须拒绝该角色；其余本人角色和亲友角色支持添加、移除与批量对比；
-   对比角色采用紧凑概览并支持整体折叠；折叠后保留添加角色和展开入口，且不清空当前角色、分类或筛选状态；
-   成就状态、地图、搜索、重置与导出统一放在对比矩阵顶部；状态筛选保留“共同未完成（推荐组队）”“共同已完成”和各参与角色的“未完成/已完成”组合，冲突条件不可同时选择；添加角色归入角色概览，避免在筛选区重复；重置清空完成状态、恢复全部分类、全部地图和空关键词；
-   分类与完成进度保持相同的主从语义：未选择一级分类时为紧凑单列，选择一级分类后左侧保留一级目录、右侧展示二级目录；一级和二级分类都直接联动矩阵标题与结果；
-   对比与完成进度统一每页 15 项，分类与矩阵顶部对齐并随内容自然增高，整页纵向滚动；不再设置固定工作区高度、内部纵向滚动或悬浮遮挡条目的表头，分页跟随列表底部。折叠角色概览只收起概览内容，不改变滚动策略；
-   总资历、分类完成率、单项成就完成状态使用同一组筛选条件；
-   多角色横向扩展只允许发生在对比矩阵容器内，不能撑宽页面；
-   导出内容必须与当前筛选结果一致，且页面与 Excel 从同一份动态维度定义生成列，未知新维度也不能被丢弃；
-   成就图片与文字块顶部对齐；没有地图时不渲染地图，分类为空时不显示占位分类；隐藏同步完成率，成就名称下展示可换行的真实描述。

### 4.3 渡劫方案

-   方案详情按“页头 / 方案概览 / 咨询记录 / 方案成就”组织，统一紧凑留白和卡片圆角。方案名只在详情页头显示一次，概览直接使用“方案概览”标题；本地编辑时仍显示编辑方案名。
-   页头保留唯一“渡劫咨询”入口，下方仅展示“咨询记录”、历史详情及分页，不再重复“咨询专家”按钮；空记录使用简短文字，不显示大幅空态插画。记录组件持续挂载，保留无记录、失败重试及已有待回复咨询分流能力。
-   成就表使用“方案成就”标题及“筛选和排序仅影响当前展示，不会修改方案”说明，移除开发侧的接口、维度来源和评分公式说明。表格局部横向滚动，不以过大的固定最小宽度强制宽屏横滚；图文与单元格顶部对齐。
-   保留方案列表、创建、编辑、删除和详情流程；
-   方案详情头部在桌面保持单行：返回入口、详情标题、方案名与操作同层展示；外层保留高度统一、宽度随文案紧凑适配的“成就团长指点”和“更多”按钮，编辑与删除收进“更多”，展开项沿用 OS 表格的完整等宽按钮形态（当前最小宽度 `88px`）；官方方案的“更多”仅展示“复制为我的方案”；窄屏允许头部操作换行；
-   页面保留方案名称、当前角色和目标资历的基础设置；现行创建入口为正式服“系统推荐”抽屉，没有独立的旧玩家自选生成入口。抽屉与页面共用基础设置，分类、维度和方向偏好的重置不清空基础设置；
-   系统推荐请求后端，由服务端给出候选资格、分组、初始顺序、当前资历和阶段。分类与权重设置作为偏好提交；前端补充展示信息并维护玩家调整后的草稿，不重新执行 `stage-v1` 评分或本地门派过滤；旧规则仅保留在纯函数与历史方案兼容说明中；
-   桌面抽屉左侧设置偏好、右侧预览；窄屏使用“预览 / 偏好设置”切换。初次打开由玩家主动开始推荐；关闭再打开保留分组顺序、项目调整、筛选和当前浏览位置。角色、客户端或偏好变化会使旧推荐失效，新推荐或主动恢复会重置草稿；
-   推荐预览区分当前候选和待开放活动，按当前组及主动展开的同地点组加载详情、难度与标签；各类请求独立显示失败和重试，展示数据缺失不改动推荐顺序与资格。待开放活动不进入当前保存清单；
-   推荐摘要显示服务端快照时间并标注 `UTC+8`，时间缺失或非法时显示“同步时间未知”；“查看同步指引”新开角色同步说明页并保留当前草稿，明确提示玩家完成游戏内同步后再刷新推荐。刷新推荐本身不执行同步；
-   待开放活动使用公开标签名称和服务端开放时间，名称缺失时保留标签编号，时间缺失时提示未知；排除原因提供可展开的分项计数，未知原因仍可见，各原因可能重叠，不展示推算的去重排除总数；
-   推荐预览支持移动分组、组内与跨组移动项目、删除和恢复原始推荐；“全部候选 / 只看已入选”与名称、地图、分类筛选只改变浏览结果，保存清单始终按调整后顺序计算，不取当前可见列表；
-   目标缺口使用后端当前资历，按草稿顺序选取达标所需的最短前缀；显示入选数量、预计获得、预计达成资历和剩余缺口或超出点数。只在必需前缀内校验点数，缺失时禁止保存；用尽候选仍不足目标但点数完整时允许保存，并明确显示缺口；
-   现有方案详情、进度、本地编辑和分类计数继续使用 `general=1`，不额外按 `visible` 过滤；本地添加只取当前角色未完成、资历点数大于 `0` 的成就。分类按名称合并、ID 去重，未完成数量为 `0` 的分类隐藏；该兼容口径不用于二次过滤后端推荐结果；
-   本地方案编辑、分类未完成数量和“添加成就”继续通过 `school-v1` 排除门派不可完成项：任务与武学按明确门派目录限制，无相楼招式全门派可用，风雨江湖路第二幕按成就 ID 映射门派；显式 `restriction.school` 优先。规则不用于推断后端的门派或标签资格；
-   进入本地编辑态的路线允许增删成就，重复项不可添加；每次变更同步重算清单项数、预计获得、达成后资历、目标缺口、耗时、难度和成本汇总，保存内容以调整后的路线为准；方案查看详情保持只读；
-   方案管理使用紧凑响应式卡片：大屏四列、常规桌面三列、平板两列、手机单列；卡片不展示通用方案图标，来源标签放在标题前，描述固定展示在标题下方且缺失时显示“—”，其后展示三项核心数据和完成率；整张卡片支持点击或键盘进入详情，列表不保留查看、编辑、复制或删除操作；已有方案的编辑、删除和复制入口集中在详情页，官方推荐使用暖金标识，玩家方案使用黛青标识；
-   路线表按公共定义动态展示和排序难度维度，所有维度采用 `0~5` 等级的低分优先语义；公共接口没有成本档字段，因此不显示成本档筛选，也不在前端推导；
-   同步完成率整列隐藏；标签、门派限制和路线备注等可选整列仅在当前表格至少一条记录有值时出现；单条记录没有地图时仍不显示地图，名称下补充可换行的成就描述；
-   推荐使用公共详情、难度和标签数据增强展示，已保存方案与本地编辑路线使用相同公共维度定义；显示层不自行补写后端推荐规则；
-   写操作需要明确确认、失败反馈和可恢复路径；删除方案必须二次确认，仅在删除成功后自动返回方案列表。
-   “成就团长指点”已接入咨询服务，仅本人正式服方案显示入口；可选择角色和专家、提交问题、查看当前方案及角色完成信息、接收建议和评价。已有待处理咨询时进入该咨询详情；当前交互不包含双版本方案改写。

## 5. 响应式规则

-   页面根节点不得出现整体横向滚动；
-   桌面内容充分使用可用宽度，不设置旧版 `960px` 固定内容宽度；
-   平板工具栏允许换行，筛选项保持清晰分组；
-   手机页签可横向滚动，指南按钮固定可见；
-   表格、对比矩阵和分类长列表只在自己的容器内滚动；
-   触控按钮高度不低于 36px，核心操作建议不低于 44px；
-   长角色名、服务器名、成就名和四语言文案不得覆盖操作按钮。

## 6. 样式作用域

新版外壳根类统一为 `.c-achievement-workbench`，所有专有样式限定在资历宝典根节点内。完成进度、亲友对比和渡劫方案均已移除旧路由主题类；旧总览、对比、渡劫与表单主题文件，以及旧 Web 总览/分类图片素材已从项目清理。小程序/App 使用的 `wiki_miniprogram` 资源保持独立，不在清理范围内。

三个 Tab 只属于一级路由：完成进度、亲友对比、渡劫方案。二、三级路由默认不渲染 Tab 和使用指南，并移除一级外壳的边框、背景与内边距，由子页面自己的返回入口和页面容器承担导航及视觉层级。一级路由通过 `meta.workbenchPrimary=true` 显式加入 Tab 外壳；新增子路由无需额外配置，默认保持独立。完成进度不再设置常规、五甲、隐藏或绝版成就子路由，四类信息统一在一级页面完成展示和筛选；渡劫方案详情使用 `/leap/:id`，旧的 `/leap?id=...` 自动重定向到详情路由。

禁止通过修改公共 `Pvx*` 组件或全局 Element Plus 样式来完成资历宝典专有视觉。

## 7. 验收矩阵

至少覆盖：

-   `1920 × 1080`、`1440 × 900`、`1280 × 800`；
-   `1024 × 768`、`768 × 1024`；
-   `414 × 896`、`390 × 844`、`320 × 568`；
-   简体中文、繁体中文、英文和越南文；
-   未登录、无角色、加载中、失败、空数据、单角色和多角色；
-   有新字段、部分新字段和全部新字段缺失三种数据情况。

所有尺寸都需确认页签、指南入口、内容滚动、长文本和局部表格没有遮挡或页面级溢出。
