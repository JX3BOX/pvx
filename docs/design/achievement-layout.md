# 资历宝典页面设计规范

> 最后更新：2026-09-03。本文记录当前确认的最终交互，不保留被后续反馈替换的中间方案。

## 1. 适用范围

本文描述普通 Web 资历宝典 `/achievements`、`/achievements/compare`、`/achievements/leap` 的新版信息结构、视觉语言和响应式规则。业务状态、接口边界和实施阶段见
[`../project/achievement.md`](../project/achievement.md)，统一字段协议见
[`../agents/achievement-workbench-data-contract.md`](../agents/achievement-workbench-data-contract.md)。

新版以“魔盒成就百科”交互原型及确认稿图 1 为功能与结构参考。旧资历宝典代码、侧栏和深色国风背景不再是保护对象。

## 2. 页面骨架

三页必须共享同一个工作台外壳：

1. 站点公共导航与 Header；
2. 暖纸色工作台容器；
3. “完成进度 / 亲友对比 / 渡劫方案”顶部页签；
4. 独立的“资历宝典使用指南”入口；
5. 当前路由的业务内容；
6. 公共返回顶部与 Footer。

模块页签在所有 Web 断点保持顶部布局，不再切换为桌面侧栏。页签支持键盘焦点、明确激活态和移动端横向滚动；使用指南在窄屏可收敛为图标按钮，但必须保留可访问名称。

## 3. 视觉语言

-   页面底采用低对比暖纸色，可使用细微纤维纹理和青灰色晕染，不使用大面积深色游戏背景；
-   主内容表面以米白、浅暖灰为主，边框低对比、阴影克制；
-   主强调色使用黛青/青灰，第二强调色使用暖金；
-   状态色仅用于完成、警告、绝版、隐藏和错误等语义，不作为大面积装饰；
-   数字使用等宽或制表数字特性，进度、点数、成本等级应易于纵向比较；
-   允许原有游戏图标、角色头像和业务美术继续出现在内容区，但不决定新版外壳配色。

## 4. 三页信息结构

### 4.1 完成进度

按以下顺序实现：

1. 当前角色、排序和筛选；
2. 总资历、总完成率、已完成成就数；
3. 常规、五甲、隐藏、绝版等分类总览；点击常规或五甲卡片直接修改主页面成就列表的档位筛选，隐藏卡片跳转 Wiki 的隐藏成就维护文章，绝版卡仅展示统计；
4. 主页面的成就列表顶部提供档位、完成状态、地图、排序、搜索和重置；档位仅包含常规、五甲两项并默认常规，排序默认保留原始目录顺序，同时提供未完成优先等排序选项；重置恢复常规档位、全部状态、全部地图、默认排序、空关键词和全部分类；分类由左侧分类进度列表直接控制，不重复展示分类下拉；右侧列表标题不追加“成就”，一级分类直接显示一级名称，二级分类显示“一级 / 二级”，选择全部时显示“全部”；
5. 分类进度恢复旧版一级分类图标；桌面展开一级分类后采用左侧一级目录、右侧二级目录的主从双栏，左栏仅保留图标、名称、完成率和进度条，窄屏降级为上下布局；一级和二级分类都可联动筛选全部成就列表；
6. 难度、预计耗时等新字段有值时进入排序和展示，无值时显示“—”。

成就列表继续保留奖励信息。当前页存在奖励引用时展示奖励字段：物品奖励加载图标、详情悬浮卡片和物品链接；无法解析的其他奖励使用通用奖励标识，加载失败显示不可用提示，无奖励的记录显示“—”。奖励物品按当前页批量读取并复用会话缓存。

总览与分类总览采用紧凑高度，并允许整体折叠。折叠入口位于角色栏右侧；折叠后保留角色切换、同步状态和展开入口，不影响当前角色、分类或成就筛选状态。折叠态下方左右工作区按剩余可视高度等高展示，确保页面主体可在一屏内完整呈现；分类进度和成就列表的超出内容分别在自身容器内部滚动。展开二级分类后恢复一级、二级主从双栏，并继续保持工作区整体高度不撑破当前视口。

主页面的分类筛选和分类进度沿用旧版目录口径：仅展示包含 `general=1` 常规成就的顶层分类，排名、江湖百态等仅包含其他档位成就的辅助目录不进入主分类。未展开二级分类时，一级分类只使用单列，不为了填满宽度拆成两列；超出工作区高度后使用内部滚动。

常规和五甲成就不设置独立二级路由；两张分类总览卡片与主列表档位下拉使用同一个 `filters.tier` 状态，点击卡片后 URL 不变，并立即刷新下方列表。隐藏成就不参与档位筛选，分类总览卡片跳转到 Wiki 隐藏成就文章；绝版成就不参与档位筛选，也不提供点击入口。

### 4.2 亲友对比

-   当前角色沿用完成进度页最近选择的本人角色并固定为首个基准角色，不提供移除入口，父页面删除逻辑也必须拒绝该角色；其余本人角色和亲友角色支持添加、移除与批量对比；
-   对比角色采用紧凑概览并支持整体折叠；折叠后保留添加角色和展开入口，且不清空当前角色、分类或筛选状态；
-   成就状态、地图、搜索、重置与导出统一放在对比矩阵顶部；状态筛选保留“共同未完成（推荐组队）”“共同已完成”和各参与角色的“未完成/已完成”组合，冲突条件不可同时选择；添加角色归入角色概览，避免在筛选区重复；重置清空完成状态、恢复全部分类、全部地图和空关键词；
-   分类与完成进度保持相同的主从语义：未选择一级分类时为紧凑单列，选择一级分类后左侧保留一级目录、右侧展示二级目录；一级和二级分类都直接联动矩阵标题与结果；
-   桌面分类区与对比矩阵等高，分类、二级分类和矩阵内容分别在模块内部滚动；折叠角色概览后按剩余视口高度扩展工作区；
-   总资历、分类完成率、单项成就完成状态使用同一组筛选条件；
-   多角色横向扩展只允许发生在对比矩阵容器内，不能撑宽页面；
-   导出内容必须与当前筛选结果一致；
-   新增的难度、耗时和成本字段有值后才启用相关筛选与比较。

### 4.3 渡劫方案

-   保留方案列表、创建、编辑、删除和详情流程；
-   方案详情头部在桌面保持单行：返回入口、详情标题、方案名与操作同层展示；外层保留高度统一、宽度随文案紧凑适配的“成就团长指点”和“更多”按钮，编辑与删除收进“更多”，展开项沿用 OS 表格的完整等宽按钮形态（当前最小宽度 `88px`）；官方方案的“更多”仅展示“复制为我的方案”；窄屏允许头部操作换行；
-   方案名称、当前角色和目标资历为两条生成路径共用的方案基础设置，统一放在系统推荐与玩家自选之前；自选区域的“重置条件”只恢复分类、地图、难度和排程策略，不清空共用设置；
-   方案生成同时保留“系统推荐”和“玩家自选”两条路径：系统推荐先按当前角色资历阶段与未完成成就池推荐一级分类，再生成具体路线；玩家自选继续保留分类、地图、难度与排程策略，不因推荐功能降低自由度；
-   第一版阶段规则为入门期 `<30000`、成长期 `30000~74999`、冲刺期 `75000~99999`、渡劫期 `>=100000`，配置与六维权重统一维护在 `src/utils/achievementLeap.js`；权重版本为 `stage-v1`，维度包括资历收益、耗时效率、低难度、低金钱成本、低时间成本和低随机性；缺失维度按可用权重重新归一化，不使用占位值参与推荐；分类最终排序由候选质量 `75%`、未完成存量 `15%`、可获得资历池 `10%` 聚合，防止只按分类体量机械推荐；
-   目标点数、难度上限、地图/分类、未完成状态等条件共同生成候选项；
-   渡劫方案只使用 `general=1` 的成就，不额外按 `visible` 字段过滤；分类标签、未完成数量、路线生成、方案详情与实时进度统一遵循该口径，`general=0/2/3` 均不参与；“参与规划的分类”展示当前角色的未完成成就数量，不展示分类资历总点数，未完成数量为 0 的分类直接隐藏；
-   推荐候选池、玩家自选候选池、分类未完成数量和本地路线“添加成就”必须统一排除当前角色门派不可完成项。接口字段接入前使用 `school-v1` 前端规则：任务仅限制名称精确对应门派的二级目录，武学仅限制各门派招式且无相楼招式全门派可用，风雨江湖路第二幕按成就 ID 映射门派；角色门派同时兼容门派 ID、门派名和心法名。接口提供 `restriction.school` 后以显式字段为准，前端规则只作兼容回退；
-   本地生成或进入编辑态的冲刺路线允许逐项删除成就；删除后必须同步重算清单项数、预计获得、达成后资历、目标缺口、耗时、难度和成本汇总，保存内容以删除后的路线为准；方案查看详情保持只读；
-   本地生成或进入编辑态的路线允许搜索并添加当前角色未完成、`general=1` 且资历点数大于 0 的成就；重复项不可再次添加，添加后与删除使用同一汇总重算逻辑；
-   方案管理使用紧凑响应式卡片：大屏四列、常规桌面三列、平板两列、手机单列；卡片不展示通用方案图标，来源标签放在标题前，描述固定展示在标题下方且缺失时显示“—”，其后展示三项核心数据和完成率；整张卡片支持点击或键盘进入详情，列表不保留查看、编辑、复制或删除操作；所有写操作集中在详情页，官方推荐使用暖金标识，玩家方案使用黛青标识；
-   逐步接入“预计分钟、金钱、时间、运气、综合难度、门派限制、路线备注”等字段；
-   缺少字段时表格显示“—”，且依赖该字段的排序、筛选和自动建议必须禁用或降级；
-   写操作需要明确确认、失败反馈和可恢复路径；删除方案必须二次确认，仅在删除成功后自动返回方案列表。
-   “成就团长指点”在接口接入前仅模拟确认、提交中和已提交状态，不调用现有方案接口；真实流程必须由服务端按方案与角色重新查询数据，审核结果同时保留原方案与调整方案。

## 5. 响应式规则

-   页面根节点不得出现整体横向滚动；
-   桌面内容充分使用可用宽度，不设置旧版 `960px` 固定内容宽度；
-   平板工具栏允许换行，筛选项保持清晰分组；
-   手机页签可横向滚动，指南按钮固定可见；
-   表格、对比矩阵和分类长列表只在自己的容器内滚动；
-   触控按钮高度不低于 36px，核心操作建议不低于 44px；
-   长角色名、服务器名、成就名和四语言文案不得覆盖操作按钮。

## 6. 样式作用域

新版外壳根类统一为 `.c-achievement-workbench`，所有专有样式限定在资历宝典根节点内。完成进度、亲友对比和渡劫方案均已移除旧路由主题类；旧总览、对比、渡劫与表单主题文件，以及旧 Web 总览/分类图片素材已从项目清理。小程序/App 使用的 `wiki_miniprogram` 资源保持独立，不在清理范围内。

三个 Tab 只属于一级路由：完成进度、亲友对比、渡劫方案。二、三级路由默认不渲染 Tab 和使用指南，并移除一级外壳的边框、背景与内边距，由子页面自己的返回入口和页面容器承担导航及视觉层级。一级路由通过 `meta.workbenchPrimary=true` 显式加入 Tab 外壳；新增子路由无需额外配置，默认保持独立。完成进度不再设置常规、五甲、隐藏或绝版成就子路由，四类信息统一在一级页面完成展示和筛选；渡劫方案详情使用 `/leap/:id`，旧的 `/leap?id=...` 自动重定向到详情路由。

禁止通过修改公共 `Pvx*` 组件或全局 Element Plus 样式来完成资历宝典专有视觉。

## 7. 验收矩阵

至少覆盖：

-   `1920 × 1080`、`1440 × 900`、`1280 × 800`；
-   `1024 × 768`、`768 × 1024`；
-   `414 × 896`、`390 × 844`、`320 × 568`；
-   简体中文、繁体中文、英文和越南文；
-   未登录、无角色、加载中、失败、空数据、单角色和多角色；
-   有新字段、部分新字段和全部新字段缺失三种数据情况。

所有尺寸都需确认页签、指南入口、内容滚动、长文本和局部表格没有遮挡或页面级溢出。
