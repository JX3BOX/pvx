# PVX 多屏与移动端适配规范

## 1. 文档定位

本文以已验收的捏脸数据、体型数据页面为实现基线，统一说明 PVX 在大屏桌面、常规桌面、平板和手机 Web 中的适配方式。

通用视觉、容器、卡片和设计令牌继续以 `docs/design/pvx-visual-style-guide.md` 为准；本文专门描述屏幕变化、布局降级和多屏验收。

## 2. 统一响应式 Web

PVX 当前只维护浏览器 Web 页面，不再根据小程序或 App 宿主切换另一套路由、组件和原生跳转协议。

桌面、平板和手机浏览器默认使用同一个 Vue 页面，通过 CSS 断点适配可用宽度、输入能力和方向；响应式变化不改变接口、路由语义或业务状态。

少数内容结构差异很大的页面可以按视口宽度加载独立的手机 Web 组件。目前保留的例子是奇遇珍券竖版和技艺助手手机版。它们仍属于普通 Web，必须继续渲染全局导航、页脚和浏览器登录流程，不能调用原生宿主协议。

业务代码不得再通过 User-Agent、DOM 环境类或查询参数恢复已经下线的宿主分流。仅当同一 Web 业务确实需要不同页面结构时，才允许使用视口判断，并同时验证窗口尺寸变化和直接访问子路由。

### 2.1 已下线的宿主适配边界

以下能力不再属于 PVX 本地页面：

- 小程序/App 专用入口、路由、页面、组件、样式和原生跳转协议；
- `isMiniProgram()`、`isApp()`、`.v-miniprogram`、`.wechat-miniprogram` 等宿主检测或环境类分流；
- 微信 JS SDK 和只为宿主页面服务的前端依赖；
- QQBot 独立多页面入口、`/qqbot/pvx` 路由及 Adventure、Pet、Horse、Book、Furniture、Reputation 等模块中的 Bot 图片页面渲染分支；
- 资历宝典的目录、列表、对比目录和对比成就等旧宿主专用子路由。

各业务入口统一加载普通 Web 页面。删除宿主专用实现后，不得用空页面、兼容壳或同名占位入口继续维持旧页面；旧宿主链接应由其迁移后的项目或发布侧处理。

### 2.2 QQBot 与刷图保留边界

下线 QQBot 本地图片页面不等于删除普通 Web 中的 Bot 业务能力。以下内容继续保留：

- 普通详情页的 `PvxRobotTip`，用于展示 QQBot 账号、复制固定协议命令和说明如何获取攻略；
- `PvxSingleAdminDrop` 的管理员刷新任务；
- `src/service/pvx.js`、`src/service/wiki.js` 等现有刷图服务调用；
- 奇遇珍券横版与竖版页面中的 `refreshAchievementsTask`，以及角色、服务器和横竖版模式参数；
- QQ 群反馈、协议关键词和对应国际化外围文案。

普通页面只负责引导和提交任务，不再承担 QQBot 图片页面的布局、数据拼装、图片预加载或 `window.__READY__` 抓图就绪状态。服务端任务、CDN 图片和已部署静态内容不由前端页面清理处理。

### 2.3 本地开发服务

`vue.config.js` 的多页面入口只在开发服务启动时读取。新增或删除页面入口后，必须停止并重新启动 `npm run dev`；刷新浏览器不会重新加载该配置。

若删除 QQBot 入口后仍出现 `Can't resolve 'src/pages/qqbot/index.js'`，说明当前开发进程仍持有旧的页面配置。先重启开发服务，再判断是否存在代码引用；不得为了消除旧进程报错而恢复已经下线的入口文件。

## 3. 断点基线

项目断点以 `@jx3box/jx3box-common/css/var.less` 中的变量为准，新样式必须引用变量，不复制魔法数字。

| 屏幕区间 | 当前变量/范围 | 主要策略 |
| --- | --- | --- |
| 手机 | `@phone`，当前 `≤ 720px` | 单列、触控优先、操作重排 |
| 竖屏平板 | `721px–@ipad-y`，当前至 `1023px` | 主内容单列或紧凑双区块 |
| 横屏平板 | `1024px–@ipad`，当前至 `1133px` | 保留工具栏一行，内容弹性收缩 |
| 小屏桌面 | `1134px–1440px` | 完整功能，卡片区允许局部横向浏览 |
| 常规桌面 | `> 1440px` | 完整布局和稳定内容密度 |
| 大屏桌面 | `@smallpc` 附近及以上，当前 `1680px+` | 增加可见内容，不拉大基础间距 |

注意：项目 `src/assets/css/var.less` 中关于外部断点的注释可能滞后，实际编译值以公共包变量为准。升级公共包后应重新核对断点表现。

断点只用于布局发生结构变化的地方。内容本身能通过 Grid、Flex、`minmax()`、`min-width: 0` 自适应时，不应新增额外断点。

## 4. 页面容器

沿用全站视觉规范中的容器基线：

| 场景 | 最大宽度/内边距 |
| --- | --- |
| 内容最大宽度 | `1440px` |
| 常规桌面水平内边距 | `32px` |
| 中等屏幕水平内边距 | `24px` |
| 手机水平内边距 | `16px` |
| 常规桌面垂直内边距 | `32px` |
| 手机垂直内边距 | `20px` |

`1440px` 是普通内容页默认上限，不是所有页面的强制上限。信息密集型列表或详情经业务评审需要利用大屏空间时，可以在模块专有根节点内将内容容器改为全宽，但必须继续使用上述桌面、平板和手机安全边距；不得修改 `PvxPageShell` 的公共默认值，也不得让未改造页面被动变宽。

主容器必须满足：

- `box-sizing: border-box`，宽度计算包含内边距；
- 子项可收缩时设置 `min-width: 0`；
- 页面级禁止横向滚动；
- 只有卡片带、表格、参数 Tab 等明确内容容器可以局部横向滚动；
- 首屏保持合理最小高度，但移动端避免仅依赖传统 `100vh` 造成浏览器地址栏跳动；新代码优先评估 `100dvh` 并保留兼容回退。

## 5. 普通 Web 列表页

### 5.1 桌面端

- 筛选、搜索、解析和发布入口位于同一工具层级。
- 卡片宽度保持稳定，列数根据内容区实际宽度计算。
- 大屏解除容器上限后，应同步提高承载复杂信息卡片的最小宽度，避免只增加列数导致卡片内容过密；优先使用 `auto-fill + minmax()`，而不是按视口硬编码列数。
- 总览卡片带在空间不足时只允许自身横向滚动，不能撑宽页面。
- 全部列表使用 Grid/Flex 自动排布，最后一项不能裁切或被 `space-between` 拉开异常间距。
- Face 与 Body 通过 CSS 自定义属性表达卡片高度和图片比例差异，不复制整套布局。

### 5.2 平板端

- 页面内边距收紧到约 `20px`，分区内边距收紧到 `16px`。
- 业务 Tab 不再强制 Sticky，避免占用有限高度。
- 竖屏时工具栏允许换行，搜索输入框保持可用最小宽度。
- 横屏平板保持“类型 + 筛选 + 弹性搜索框 + 操作入口”同一行，搜索框承担剩余宽度。
- 卡片总览从多列区块降为单列区块，卡片本身不随容器无限拉伸。

### 5.3 手机 Web

- 页面与分区采用单列，工具栏按“类型、筛选/搜索、主要操作”重排。
- 图鉴类工具栏优先使用两行结构：分类胶囊在第一行横向浏览，第二行由固定尺寸筛选按钮和占据剩余宽度的搜索框组成；筛选按钮与搜索框保持同一高度和统一间距。
- 页面级 Hero 的服务器、区服等公共选择器移动到标题下方并占满可用宽度；条件只维护一份状态，不能在各子页重复初始化。
- 类型选择可以局部横向滚动，选项不可被压缩到不可点击。
- 主要操作按钮占满可用宽度。
- 卡片列表居中展示稳定卡片宽度；如果业务需要双列，必须先验证 320px 宽度和长语言。

书籍大全的响应式列表遵循以下补充规则：

- 卡片模式在大屏按可用宽度增加列数，书卷封面保持原始比例；手机端允许双列，但卡片宽度、封面和说明区必须共同收缩，说明完整换行，不使用省略号隐藏内容；
- 同套书籍横向卡片区按内容自然排布，空攻略提示与后续社区区块之间只保留页面标准间距，不使用固定高度占位；
- 列表模式在桌面保留表头，在手机隐藏表头并把每条记录转换为单列字段卡；标签列保持稳定宽度，值列设置 `min-width: 0` 和长文本换行，页面不得出现横向滚动；
- 名称字段中的物品图标和名称采用竖排居中结构。物品接口可用时由物品组件展示名称；接口最终失败时，备用书名也放在图标下方，保持两种状态的几何结构一致；
- 分类、搜索、卡片/列表切换在手机端允许换行或分行，不能挤压列表内容；英文和越南文分类词必须完整可辨。
- 信息看板在手机端优先改为单列完整卡片；卡片本身已经能够完整展示时，不保留无意义的横向滚动、滚动条或切换箭头。
- 区块标题右侧的低频管理操作可以仅显示图标，点击区不得小于业务验证后的紧凑尺寸，并必须提供可访问名称。
- 筛选浮层宽度不得超过 `100vw - 32px`，相对视口居中。
- 分页器可隐藏不适合手机的 total、jumper 等信息，保留明确的上一页、下一页或加载更多能力。
- 英文、越南文标签允许两行，卡片为第二行预留高度，不能靠缩小字号硬塞。
- 图鉴概览的接口请求数量不能直接等于手机可见列数。参考 Face / 坐骑的已落地规则，概览每个分类至少准备 `6` 条，进入分类后准备两行数据、手机至少 `12` 条；视觉列数、概览数量和分页 `pageSize` 必须分别表达，不能在发请求前互相覆盖。
- 分区标题只有“标题 + 查看全部”时应优先保持同一行；进入分类后的结果数量、视图切换等复杂操作可以换到下一行，不能通过压缩标题宽度把中文标题挤成逐字竖排。
- 列表内承载业务信息的地图不能仅因窄屏适配困难而隐藏。第三方地图支持总览模式时，手机优先切换到完整总览并使用地图原始比例铺满内容宽度；地图与下方列表保持明确间距，改变视口后需要重新计算组件尺寸。

## 6. 普通 Web 详情页

### 6.1 桌面端

- 预览区、购买/下载区、作者信息和相关推荐保持明确主次关系。
- 图片容器有固定比例或稳定高度，切换图片不引发布局跳动。
- 购买和下载是主要操作，不能被装饰图、长标题或标签遮挡。
- 相关推荐按稳定卡片宽度排列。

### 6.2 平板端

- 详情主内容允许换行，购买区降到预览区下方并占满内容宽度。
- 装饰性图片可以隐藏，业务价格、权限和下载信息必须保留。
- 参数分类和相关推荐只在各自容器内横向滚动。
- 购买按钮和复制码区域改为垂直排列，触控区域保持稳定。

### 6.3 手机 Web

- 作者头部改为单列，可隐藏不影响识别的装饰头像，但保留作者名称和必要身份信息。
- 顶部导航允许换行，低频管理员操作可收进菜单或在手机布局中隐藏；业务主操作不能直接消失。
- 价格和游戏内收费提示允许换行并居中展示。
- 轮播宽度使用可用内容宽度，左右保留安全边距。
- 相关推荐采用横向卡片带时必须显示可滚动线索，并保证页面本身不横向滚动。
- 弹窗、确认框、图片预览和下载提示均需单独验证触摸操作。
- 图鉴详情的多阶段选择（如声望阶段奖励）在手机端可改为局部横向滑动卡片带，并使用 `grid-auto-flow: column`、稳定的可见卡片宽度和滚动吸附；奖励正文仍位于卡片带下方，不能让所有阶段纵向堆叠，也不能把横向滚动扩散到页面。
- 固定字段卡在英文、越南文等长语言下优先把标签和值改为上下排列，并对两者设置 `min-width: 0` 与 `overflow-wrap`；游戏源数据值不应因标签过长被截断。
- 带胶囊标签的说明行必须使用明确的 Flex 垂直居中。标签、名称和短说明在单行时共享同一垂直中心；允许换行时应由内容自然增高，不能针对长语言统一改成顶部对齐而破坏常见单行状态。

## 7. 数据解析页

Face / Body 共用 `ParsePage.vue` 外壳，差异通过 `type` 和对应语言键传入。

- 桌面端保持“导入说明—上传区—能力提示—解析结果”的清晰顺序。
- 上传区域需要足够点击面积，并同时支持点击与拖拽时的状态反馈。
- 平板端参数网格减少列数，标题或总价占独立行，不能挤压数值。
- 手机端上传区收紧但高度不低于可操作阈值；提示卡改为单列。
- 手机端参数 Tab 可在自身容器横向滚动，结果项保持标签、数值和控件对齐。
- 隐私提示可收为图标，但必须提供 tooltip、aria-label 或等价可访问说明。
- 文件选择、解析失败、清空重选和第三方 facedat 组件均要验证。

## 8. 独立的手机 Web 页面

独立手机 Web 页面只用于同一业务在窄屏下确实需要不同信息结构的场景：

- `/pvx/adventure/portrait` 是普通手机 Web 的奇遇珍券竖版页，保留全局导航、页脚、浏览器登录、角色绑定和“刷新画卷”任务。
- `/pvg/manufacture` 可以按视口加载 `ManufactureMobile.vue`，但与桌面版共享客户端、服务器、角色、购物车和计划数据语义。
- 页面切换只依据可用宽度，不依据宿主类型；直接访问手机子路由时也必须可独立工作。
- 主滚动区与抽屉滚动区职责分离，打开抽屉时避免背景穿透滚动。
- 加载流程必须区分 loading、完成、空数据和失败状态，不能重复请求。
- 手机页面可以采用触控友好的独立组件，但不得另建一套只在某个宿主中成立的业务协议。

## 9. 游戏内嵌兼容边界

奇遇详情仍保留低版本游戏插件和无界 WebView 的跳转兼容。该逻辑按浏览器能力、游戏 WebView 特征和业务参数判断，与响应式手机 Web 无关。

- 不得把游戏内嵌兼容重新抽象为小程序/App 页面分流。
- 改动奇遇路由或详情加载时，需要单独回归普通浏览器、低版本 Chrome 和无界 WebView。
- 游戏内嵌跳转只负责选择目标页面，不得影响普通 Web 的主题类、导航、社区和管理操作。

## 10. 图片、触控与可访问性

- 触控目标建议不小于 `44 × 44px`；相邻目标保留足够间距。
- Hover 样式仅放在 `@media (hover: hover) and (pointer: fine)` 中，触屏不能依赖 Hover 才展示操作。
- 图片使用明确的 `aspect-ratio`、宽高或容器约束，避免加载前后跳动。
- 地图等按容器尺寸计算内部画布的第三方组件，外层改变宽度后必须触发其尺寸更新；局部裁切模式只用于有明确焦点且容器尺寸稳定的桌面场景，手机展示完整地图时应使用组件的响应式总览模式，避免固定内部画布造成空白。
- 业务图片加载失败时必须在原尺寸容器内显示稳定的模块兜底图或占位图，不能暴露浏览器破图图标、失败文字或引发布局位移。
- 非装饰图片提供有效替代文本；纯装饰图片使用空 alt。
- 键盘焦点不能被 Sticky 导航遮挡，弹层必须有正确的焦点进入与返回。
- 状态不能只用颜色表达，需同时提供文本、图标或形状。
- 支持系统减少动态效果偏好时，应停用非必要位移和缩放动画。

## 11. 长语言适配

每次响应式验收至少覆盖中文、英文和越南文：

- 标题可换行或省略，但不能挤掉主要操作；
- 按钮优先弹性宽度，不设置仅适合中文的固定宽度；
- 标签组允许换行并保持垂直间距；
- 表单标签与输入区在窄屏可改为上下排列；
- 使用 `html:lang(en)`、`html:lang(vi)` 的差异规则时，必须限定在模块根节点下；
- 文案溢出应先调整布局，再考虑截断，不能把业务关键信息截断到不可理解。

## 12. 样式组织

Face / Body 当前样式职责如下：

| 路径 | 职责 |
| --- | --- |
| `assets/css/common/face-body/pc` | 普通 Web 共用列表、详情和变量 |
| `assets/css/common/face-body/parse.less` | 普通 Web 共用解析页 |
| `assets/css/face`、`assets/css/body` | 模块入口及真实差异 |
| `assets/css/modules/face-body-theme.less` | 已验收现代主题和长语言响应式修正 |
| `assets/css/modules/book-list-theme.less` | 书籍普通 Web 列表主题、工具栏、概览与多屏布局 |
| `assets/css/modules/book-detail-theme.less` | 书籍普通 Web 详情主题、阅读区、套书区与社区间距 |
| `assets/css/book/result`、`assets/css/book/card.less` | 书籍列表行、表头和书卷卡片的业务结构及窄屏降级 |
| `assets/css/adventure/treasure/mobile` | 奇遇珍券普通手机 Web 竖版布局 |

新增规则必须挂在模块根节点下。独立手机 Web 组件与同业务桌面组件共享设计令牌和业务语义，不引入宿主专用变量。只在三个以上页面稳定复用的值才提升为公共令牌。

## 14. 页面验收清单

### 布局

- 页面没有横向滚动，允许滚动的局部容器边界明确。
- 卡片不裁切、不异常拉伸，最后一项可完整访问。
- Sticky、Fixed、弹层和宿主导航互不遮挡。
- 横竖屏切换后布局和滚动位置仍可用。

### 内容

- 中文、繁体中文、英文、越南文无关键内容溢出。
- 空数据、加载、失败、无权限和下架状态均有明确布局。
- 用户内容超长、图片缺失、接口字段缺失时不破版。

### 交互

- 搜索、筛选、分页/加载更多、Tab、返回和主要操作可触摸、可键盘使用。
- 购买、支付、复制、下载、文件解析和图片预览流程未因重排改变。
- 弹层可打开、关闭、取消和提交，背景不会穿透滚动。

### 路由与边界

- 普通手机浏览器仍使用响应式 Web 页面。
- 奇遇珍券竖版和技艺助手手机版可直接访问，且仍使用普通 Web 导航、登录和链接。
- 生产构建和开发服务均不再生成 `qqbot/` 页面入口。
- 普通详情页仍可展示 QQBot 指令引导并提交管理员刷新任务，但不会进入本地 Bot 图片页面。
- 奇遇珍券横版、竖版均可提交 `refreshAchievementsTask`。
- 游戏内嵌奇遇跳转保持独立，不改变普通 Web 的路由和样式。
- 第三方组件在各断点内可滚动、可操作且没有越界。
