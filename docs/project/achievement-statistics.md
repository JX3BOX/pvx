# 资历总览统计业务规则

## 1. 文档目的

本文是资历统计口径的业务基线，适用于 PVX 资历总览、PVX 内的成就目录/对比页，以及独立 Wiki 项目的成就百科统计。页面结构、视觉与模块维护分别参考：

- [资历宝典维护说明](./achievement.md)
- [资历宝典布局规范](../design/achievement-layout.md)
- PVX 统计实现：`src/utils/achievementStatistics.js`
- Wiki 统计实现：`../wiki/src/utils/achievement-statistics.js`
- PVX 统计测试：`scripts/test-achievement-statistics.js`

本文只记录最终生效的业务规则。附录中的 `general=0`、`general=3` ID 是 `2026-08-26` 正式服接口快照，用于核验和追溯，不作为运行时硬编码名单；页面运行时始终以后端元数据为准。

## 2. 数据来源

前端使用以下三个接口：

| 接口 | 业务用途 | 说明 |
| --- | --- | --- |
| `GET /api/node/achievement/menus?general=1,2&client=std` | 获取常规、五甲的可见目录 | `children[].achievements` 可能包含任意层级数组，必须递归展开并按 ID 去重 |
| `GET /api/node/v2/achievement/points?client=std` | 获取全量成就点数和元数据 | 包含可见与隐藏成就，是总览数量、资历和分类统计的全集来源 |
| `GET /api/next2/user-achievements?jx3id={角色ID}` | 获取角色已完成成就 | 返回逗号分隔的成就 ID，前端转为字符串集合后参与交集统计 |

菜单接口只包含可见目录，不能作为资历总量上限。它继续服务于目录浏览；总览和百科统计统一使用 v2 points 的 `point`、`general` 与 `visible` 字段计算。

v2 points 的业务数据是 `ID -> [point, general, visible]` 映射。当前线上 HTTP 响应把该映射放在 `data.points` 中；若请求层已完成解包，则统计层直接接收 points 映射。

## 3. 元数据字段定义

示例：

```json
{
  "1": [20, 1, 1],
  "9000": [30, 1, 0]
}
```

数组字段顺序固定为 `[point, general, visible]`。

### 3.1 `point`

`point` 是单个成就提供的资历点数。

- `point > 0`：完成后按该数值增加角色当前资历。
- `point = 0`：保留目录浏览、搜索、详情展示和完成状态，但不进入任何资历统计数量、完成数量、剩余数量、资历或进度；该规则与 `general`、`visible` 无关。
- 负数、非数字或非有限值：视为无效元数据，整条记录不进入统计。

### 3.2 `general`

`general` 是成就业务分类码。

| 值 | 定义 | 总览处理 |
| --- | --- | --- |
| `0` | 前端业务约定为绝版/退役成就 | `point>0` 时纳入总体；角色已完成的部分纳入当前资历；不纳入“尚可提升” |
| `1` | 常规成就（接口明确值） | 按 `visible` 拆成常规可见、常规隐藏 |
| `2` | 五甲成就（接口明确值） | 按 `visible` 拆成五甲可见、五甲隐藏 |
| `3` | 前端业务约定为特殊分类，不等于绝版 | 仅 `point>0` 时纳入总体；当前快照全部为零资历，因此当前统计为 0 |
| 其他值或无效值 | 未支持分类 | 不进入总体数量和资历，只保留诊断计数 |

接口说明明确规定了 `general=1/2`；`general=0/3` 的名称和处理方式是本项目根据现有数据及业务确认建立的前端约定。不能仅凭 `general=3` 将成就判定为绝版。

### 3.3 `visible`

`visible` 表示成就是否出现在普通可见目录中。

| 值 | 定义 | 总览处理 |
| --- | --- | --- |
| `1` | 可见成就 | `point>0` 时进入当前统计作用域 |
| `0` | 隐藏成就或内部记录 | `point>0` 时才视为可统计的隐藏成就，仅在“计入隐藏成就”开启时进入总体 |
| 其他值 | 无效 | 整条记录不进入统计 |

`visible=0` 只表示目录隐藏，不代表无法完成，也不等于绝版。隐藏常规和隐藏五甲可以通过角色完成 ID 被识别为已完成；绝版由 `general=0` 判断。所有零资历记录统一退出统计，但仍可作为原始数据参与目录展示和完成状态判断。

## 4. ID 标准化与有效范围

统计前统一执行以下规则：

1. points、菜单和角色完成数据中的成就 ID 全部转为字符串。
2. 菜单中的嵌套数组递归展开；同一 ID 只统计一次。
3. 角色完成 ID 去空白、去空值并去重。
4. 只有 `general=0/1/2/3`、`point>0` 且 `visible` 有效的元数据进入统计。
5. 角色完成 ID 必须能在当前 points 元数据中命中，才贡献完成数量和资历。
6. 已完成但 points 中不存在的 ID 计入 `unknownCompletedCount` 诊断，不推测分类或点数，不进入界面统计。

因此，“绝版成就”只能识别接口仍保留元数据且标记为 `general=0` 的记录。如果某个旧成就已经从 points 接口彻底删除，前端无法仅凭完成 ID 还原其资历点。

## 5. 总体统计口径

### 5.1 隐藏开关

“计入隐藏成就”是全局统计开关，默认开启。

| 开关状态 | 总体作用域 | 分类卡 |
| --- | --- | --- |
| 开启 | 所有 `point>0` 且有效的 `general=0/1/2/3` 元数据 | 显示常规、五甲、99 烟花、常规隐藏、五甲隐藏、绝版 |
| 关闭 | 仅 `point>0 && visible=1` 的有效元数据 | 显示常规、五甲、99 烟花；隐藏常规、隐藏五甲和绝版卡不显示 |

当前快照中 `general=0` 全部为 `visible=0`，所以关闭隐藏后绝版成就不进入总体。若后端未来出现 `visible=1` 的 `general=0`，需要同步复核绝版卡的显示与作用域，不能继续假设绝版必然隐藏。

### 5.2 顶部指标

设满足 `point>0` 且处于当前开关作用域内的有效成就集合为 `S`，角色完成 ID 集合为 `C`：

- 当前资历：`sum(point(id)), id ∈ S ∩ C`。
- 当前完成数量：`|S ∩ C|`，以小字显示在当前资历后方。
- 收录资历：`sum(point(id)), id ∈ S`。
- 收录数量：`|S|`，以小字显示在收录资历后方。
- 资历进度：`当前资历 / 收录资历 × 100%`，保留两位小数并封顶 `100%`；收录资历为 `0` 时显示 `—`。
- 尚可提升：同一隐藏作用域内，所有未完成 `general=1/2` 成就的 `point` 之和。

“尚可提升”只统计当前被视为可继续获取的常规与五甲，不包含 `general=0` 绝版，也不包含 `general=3` 特殊分类。因此当角色仍有未完成绝版成就时，`收录资历 - 当前资历` 会大于“尚可提升”，这是预期结果。

### 5.3 分类统计

| 分类 | ID 条件 | 是否重复计入总体 | 未完成点数处理 |
| --- | --- | --- | --- |
| 常规成就 | `general=1 && visible=1 && point>0` | 是总体的基础组成 | 计入尚可提升 |
| 常规成就（隐藏） | `general=1 && visible=0 && point>0` | 开启隐藏时进入总体 | 开启隐藏时计入尚可提升 |
| 五甲成就 | `general=2 && visible=1 && point>0` | 是总体的基础组成 | 计入尚可提升 |
| 五甲成就（隐藏） | `general=2 && visible=0 && point>0` | 开启隐藏时进入总体 | 开启隐藏时计入尚可提升 |
| 99 烟花成就 | 65 项正向白名单，且当前元数据仍为 `general=1 && visible=1 && point>0` | 已包含在常规中，不得再次累加 | 仅专题展示 |
| 绝版成就 | `general=0 && point>0` | 按隐藏开关进入总体 | 不计入尚可提升，标注无法继续获取 |
| 特殊分类 | `general=3 && point>0` | 按隐藏开关进入总体 | 不计入尚可提升，当前不单独展示卡片 |

每张分类卡都以资历为主指标，完成数量以小字跟在资历点后方。任何 `point=0` 成就都不影响分类数量或完成数量。

## 6. 99 烟花口径

当前后端没有“99 烟花”专门分类字段，65 项正向 ID 白名单统一维护在公共库的
`@jx3box/jx3box-common/data/firework_achievement_ids.json` 中，PVX 通过 `FIREWORK_ACHIEVEMENT_IDS` 引用：

- 当前上限为 `65 项 / 13,000 资历`。
- 它是常规可见成就的专题子集，分类卡标注“已计入常规”。
- 白名单包含 ID `1573`「至死不渝」。
- ID `1707`「大公忘私！二百万」和 ID `4493`「千金散尽还复来」虽然也是 200 点，但不是 99 烟花，必须排除。
- 不得使用“所有 200 点成就”作为替代规则。
- 若后端增加稳定分类字段，应迁移到后端字段并删除前端白名单。

## 7. 已落地的界面调整

1. 用户资历与分类统计合并到同一个总览模块。
2. 顶部只保留“当前资历、收录资历、尚可提升”和资历进度；成就数量改为资历后的辅助小字。
3. 常规、五甲、隐藏常规、隐藏五甲、99 烟花和绝版使用独立分类卡。
4. 隐藏成就由一个全局开关统一控制总体与分类卡。
5. `general=0/1/2/3` 只有在 `point>0` 时才纳入数量与资历；所有零资历记录统一排除。
6. “绝版”只表示 `general=0`，不再混入普通隐藏成就；绝版卡展示已获/收录资历和完成数量，底部固定显示“已绝版，无法继续获取”。
7. 顶部不再重复显示“绝版资历”徽标；指标名称只显示“尚可提升”，不追加“不含绝版”等说明。
8. 统计卡不使用突兀的纯白描边，沿用当前暖色表面与分隔方式。

## 8. 边界与维护约束

- 隐藏不等于绝版；`visible` 不能用于推断能否完成。
- 绝版成就可以出现在角色历史完成集合中，但未完成的绝版成就不能作为可提升目标。
- `general=3` 当前全部为 `point=0`，因此当前数量与资历均为 0；若未来出现正资历，仍应进入当前/收录资历，但在业务确认可获取性前不进入“尚可提升”。
- 目录接口缺少某个 ID 不影响总体；只要 v2 points 元数据有效，它仍按 `general`、`visible` 进入统计。
- 99 烟花是展示子集，不能与常规重复相加。
- 前端不根据成就名称、点数或完成状态猜测 `general` 与 `visible`。
- 所有 `point=0` 记录均不进入资历统计；若后端未来提供独立的“可统计成就”字段，应以业务确认后的后端字段替换该前端规则。
- 搜索结果数、分页总数、批量勾选数属于内容浏览数量，不是资历进度统计；这些位置仍可包含零资历成就。

## 9. 成就百科对齐规则

独立 Wiki 项目（`../wiki`）的顶部“常规成就数/五甲成就数”和侧边目录完成统计与 PVX 使用同一口径：

1. 使用 `/api/node/v2/achievement/points`，只统计 `point>0 && visible=1` 的 `general=1/2` 成就。
2. 不再使用 `/api/node/achievement/count` 的 `count` 字段作为最终数量，因为该字段包含可见零资历成就。
3. 不再使用菜单的 `achievements_count`、`own_achievements_count` 作为最终数量；数组形式的系列成就必须递归展开，并按 ID 去重后再以 v2 元数据过滤。
4. 角色完成数量是“过滤后的目录 ID”与“角色已完成 ID”的交集。
5. 目录列表和成就详情仍展示零资历成就；只从顶部、侧栏、分类详情及对比弹窗等资历进度数量中排除。

当前百科顶部对齐值为：

| client | 常规可见 | 五甲可见 |
| --- | ---: | ---: |
| `std` | 7,555 项 / 206,080 资历 | 383 项 / 15,320 资历 |
| `origin` | 3,528 项 / 95,465 资历 | 0 项 / 0 资历 |

## 11. 验收规则

至少覆盖以下自动测试或人工验收：

1. 隐藏开启且角色未完成任何成就时，总量为 `8,463 项 / 235,720 资历`。
2. 隐藏关闭时，总量为 `7,938 项 / 221,400 资历`。
3. 任意 `point=0` 成就，无论是否可见、属于哪个 `general`，都不改变总数、完成数、剩余数、资历和进度。
4. `general=0` 的已完成点数进入当前资历，未完成点数不进入尚可提升。
5. `general=3` 当前全部为零资历，因此不进入总体数量或资历；未来只有正资历记录才可进入。
6. 隐藏开关同时改变总体作用域，并控制隐藏常规、隐藏五甲、绝版卡的显示。
7. 99 烟花完整命中 `65 项 / 13,000 资历`，且不与常规重复相加。
8. 未知完成 ID、非法 `general`、非法 `visible`、负数或非有限 `point` 不污染界面统计。
9. 成就百科顶部显示常规 `7,555 项 / 206,080 资历`、五甲 `383 项 / 15,320 资历`，侧栏目录及角色完成数量执行同一过滤规则。
