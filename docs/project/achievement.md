# 资历宝典维护说明

> 最后更新：2026-09-05。现行渡劫方案创建已接入后端推荐，并支持草稿调整与恢复；具体布局见设计规范，字段边界见统一字段协议。

## 1. 当前目标

普通 Web 资历宝典按“魔盒成就百科”原型重做，只保留三个业务模块：

-   完成进度；
-   亲友对比；
-   渡劫方案。

页面另外提供统一的“资历宝典使用指南”入口。开发环境不要求保留旧 Web 页面代码与旧视觉，后续阶段可以按模块直接替换。

## 2. 路由与范围

| 路由                     | 当前承载                      | 重做目标 |
| ------------------------ | ----------------------------- | -------- |
| `/achievements`          | `src/views/wiki/overview.vue` | 完成进度 |
| `/achievements/compare`  | `src/views/wiki/compare.vue`  | 亲友对比 |
| `/achievements/leap`     | `src/views/wiki/leap.vue`     | 渡劫方案 |
| `/achievements/leap/:id` | `src/views/wiki/leap.vue`     | 方案详情 |

`src/views/wiki/index.vue` 是三页共享外壳。旧 `/codex/achievement/*` 页面组件不再保留；如外层站点仍需兼容旧地址，应由站点路由或网关重定向到上述三个新入口。

小程序/App 专用页面仍在 `src/views/wiki/miniprogram/*`，不属于本轮直接重做范围；抽取公共数据逻辑时不得破坏其现有接口语义。

## 3. 新版边界

-   三页统一使用顶部页签，不再使用 `src/components/wiki/sidebar.vue`；
-   Web 布局只按 CSS 断点响应，不再用 User-Agent 决定结构；
-   新版采用暖纸色工作台视觉，旧 `overview-bg.png` 与深色国风背景已经移除；
-   页面根节点使用自然文档流，不得出现整体横向滚动；分类长列表、成就列表和对比矩阵可按剩余视口设置工作区高度，并只在各自容器内滚动；
-   三页共享统一字段协议和接口适配层，业务组件不得直接猜测新旧字段名；
-   接口未提供的未来字段内部保持 `null`，展示时统一为“—”；
-   `0`、`false` 等合法值必须保留，不能按缺失值处理。

## 4. 数据依赖

当前接口继续复用：

-   `src/service/achievement.js`：菜单、点数元数据、角色成就、成就详情、搜索和地图；
-   `src/service/team.js`：本人角色；
-   `src/service/wiki.js`：亲友、亲友角色和渡劫方案；
-   `src/service/achievementConsultation.js`：方案咨询、专家回复与玩家评价；
-   Vuex：当前客户端、角色和成就完成状态；
-   `xlsx`：亲友对比结果导出。

新版统一入口：

-   `src/utils/achievementWorkbench.js`：字段协议、空值规则和纯数据标准化；
-   `src/service/achievementWorkbench.js`：现有接口响应适配；
-   `src/utils/achievementRecommendation.js`：后端推荐的偏好、草稿调整、目标入选与方案保存适配；
-   `docs/agents/achievement-workbench-data-contract.md`：字段和替换规则。

CMS 玩家端只使用以下公共接口，不复用 OS 的 `/manage/...` 能力：

-   `GET /api/cms/pvx/wiki_achievement_difficulty/dimensions`：启用的动态难度维度定义；
-   `POST /api/cms/pvx/wiki_achievement_difficulty/list?client=std|origin`：成就难度维度与同步完成统计；
-   `POST /api/cms/pvx/wiki_achievement_tag/by-achievements?client=std|origin`：成就展示标签。
-   `GET /api/cms/pvx/wiki_achievement_tag/{tag_id}?client=std|origin`：公开标签详情，用于待开放活动名称。
-   `POST /api/cms/pvx/wiki_achievement_recommendation`：正式服后端推荐；数值角色 ID、阵营与偏好由适配器传递，资格和初始顺序由服务端决定。
-   `/api/cms/pvx/achievement_consultation` 及其子路由：方案咨询，具体请求见统一字段协议。

-   新增统一顶部页签和指南入口；
-   建立标准成就、角色、目录与角色完成状态适配；
-   接入原型的新字段占位与“—”展示规则；
-   暂时让三个旧业务页继续挂载在新壳内，等待逐页替换。

### 第二阶段：完成进度（已完成）

-   按原型重写总览、稀有度、分类进度、筛选和成就列表；
-   保留现有角色同步和统计口径；
-   接入难度、预计耗时等字段占位；
-   完成加载、未登录、无角色、空数据和失败状态。
-   成就列表按当前页批量读取详情；只有关键词或地图筛选启用时才调用全局搜索接口；
-   `overview.vue` 只保留路由挂载，页面编排集中在 `AchievementProgressPage.vue`，总览、筛选、分类板和列表分别作为展示组件。
-   总览区标题统一为“分类总览”；常规、五甲卡片与下方档位下拉联动，隐藏卡片跳转 Wiki 隐藏成就文章，绝版卡仅展示统计。
-   成就列表提供独立的默认排序和未完成优先排序；“重置”统一恢复常规档位、全部状态、全部地图、默认排序、空关键词和全部分类。
-   成就列表档位只保留常规、五甲并默认常规；状态、地图、排序、搜索和重置统一放在列表上方，地图继续使用有效 `RegionName` 的正式区域地图；列表保留成就奖励、物品图标和物品详情能力。
-   分类进度只统计包含 `general=1` 成就的正式一级分类，恢复原一级图标与二级分类；默认采用紧凑单列，选择一级后以左侧一级、右侧二级的主从结构展示。一级、二级都会改变右侧列表标题和结果，不再设置分类详情子页面。
-   总览支持折叠；折叠不清空角色或筛选。完成进度与亲友对比统一每页 15 项，分类与列表自然增高、整页纵向滚动，分页跟随列表底部；亲友对比保留矩阵内横向滚动。

### 第三阶段：亲友对比（已完成）

-   重写角色选择、总览比较、分类短板与对比矩阵；
-   保留亲友添加、移除、筛选组合和 Excel 导出；
-   表格只在内部横向滚动。
-   对比角色最多 4 个，默认载入路由指定角色或本人首个角色；
-   当前角色固定为首个基准角色，展示锁定状态，界面和父级删除逻辑都不得移除；其他本人角色和亲友角色仍可添加、确认后移除。
-   对比状态筛选保留原有组合语义：“共同未完成（推荐组队）”“共同已完成”，以及各参与角色的“未完成/已完成”；互相矛盾的同角色条件和与共同条件冲突的条件不可同时选择。地图、搜索、重置和导出与状态条件统一放在矩阵上方。
-   详细分析提供总资历条形对比、前两个角色的四象限交叉统计、最多 4 个角色的资历结构叠加和共同短板分类；
-   关键词/地图搜索复用统一搜索适配器，普通分类浏览仍按当前页批量读取详情；
-   难度和预计耗时继续遵守统一未来字段协议，缺失时展示“—”。

### 第四阶段：渡劫方案（已完成）

本节记录初版方案模块；当前创建流程由第七阶段的后端推荐接替，旧路线纯函数仅保留兼容用途。

-   重写方案列表、创建表单、详情和路线建议；
-   接入成本账本字段和按性价比排序；
-   保留路由查询参数与所有写操作语义。
-   初版本地路线按“目标值 - 当前资历”计算缺口，候选取当前角色未完成、`general=1` 且资历点数大于 `0` 的普通成就；分类与地图条件可叠加。现有方案读取、进度和详情仍按 `general=1` 收口，历史原始 `schema` 不用于展示非普通成就；此本地口径不用于二次过滤后端推荐；
-   旧路线纯函数保留综合难度上限、低难度优先及缺字段时高资历优先的降级逻辑；现行后端推荐失败时显示错误与重试，不调用旧路线逻辑降级生成；
-   预计分钟、金钱、时间、运气、门派限制和路线备注统一进入成本账本，缺失值显示“—”；依赖缺失字段的策略和排序禁用；
-   新方案的规划条件写入 `meta`，方案成就 ID 继续写入 `schema`；旧方案仍可查看、复制、编辑和删除；
-   路由挂载收敛到 `AchievementLeapPage.vue`，规划器、摘要、路线表、方案列表和保存弹窗使用独立组件；
-   方案名称、当前角色、目标资历继续作为共用基础设置。旧系统推荐与玩家自选的并列生成入口已被后端推荐抽屉接替；历史自选字段仍可恢复和编辑。
-   第一版 `stage-v1` 阶段阈值与权重保留在 `achievementLeap.js` 的兼容纯函数及统一字段协议中；当前页面不执行该评分，也不将它解释为后端推荐算法。
-   本地编辑候选、分类数量和添加列表统一只取当前角色未完成、`general=1`、资历点数大于 `0` 的普通成就；相同名称的目录合并并按成就 ID 去重，数量为 `0` 的分类不展示。`visible` 不参与本地渡劫过滤。
-   本地候选与分类计数继续接入 `achievementSchoolEligibility.js` 的 `school-v1`：排除任务门派、门派招式和风雨江湖路第二幕中的门派不可完成项，显式 `restriction.school` 优先；后端推荐结果不再经过该规则过滤；
-   本地生成或编辑中的路线支持增加、删除成就；重复项不可添加，每次变更后重新计算清单项数、预计获得、目标缺口、耗时、难度和成本汇总，保存时以调整后的 `schema` 为准。
-   方案列表移除查看、编辑、复制和删除按钮，整张卡片作为详情入口；详情头部收敛为单行紧凑布局，外层保留“成就团长指点”和“更多”，编辑/删除在“更多”展开后按 OS 表格使用完整按钮形态，删除二次确认并在成功后自动返回列表；成就团长指点已接入真实咨询服务，提供问题、角色完成信息、专家建议和评价，当前不实现双版本方案改写；
-   方案卡片移除通用图标，来源标签放在标题前，描述放在标题下且缺失时显示“—”；列表只负责进入详情，编辑、删除和官方方案复制均在详情操作。
-   移除旧 `leap/pc.vue`、`mobile.vue`、`form.vue`、`detail.vue` 以及旧 Web 主题文件。

### 第六阶段：公共数据接入收尾（已完成）

-   三个页面从同一公共接口读取难度维度定义；定义请求带短时缓存，失败时才使用内置五维兼容配置；
-   难度值统一使用支持 `0` 和小数的星级组件，五颗星后显示一位小数但不显示 `x/5`（可访问名称可保留该比例），显式 `null` 不再被旧字段覆盖；
-   完成进度页默认只补充当前可见页的难度和标签，用户主动选择动态维度排序后才批量补齐当前候选集；客户端或角色变化后的旧响应不得回写；
-   亲友对比矩阵与 Excel 导出共用动态维度定义、名称和顺序；同步完成率及角色样本计数均隐藏，页面及导出补充成就描述；
-   渡劫页只改造已确定路线的展示数据：补齐 `SceneID` 地图名、动态难度列与可选列；移除没有公共数据来源的成本档筛选；
-   所有成就入口（含添加、推荐、待开放活动及咨询）隐藏同步完成率，显示已有成就描述；无描述不占位、长描述可换行。保留角色和方案自身完成进度，以及无地图/无奖励不展示、常规 tag 隐藏、五甲保留、门派 tag 优先规则；
-   该阶段只完成公共展示数据接入，后续后端推荐接入与现行交互见第七阶段。

### 第七阶段：后端推荐与草稿恢复（已完成）

-   正式服创建入口使用后端推荐抽屉；页面传数值 `role_id`、`camp: "neutral"` 和分类、维度、方向偏好，候选、分组和初始排序以服务端结果为准，不上传本地完成快照，不执行 `stage-v1` 或 `school-v1` 二次筛选；
-   桌面抽屉分为设置与预览，移动端使用页签切换；初次打开主动开始推荐，关闭再打开保留草稿。角色、客户端、偏好变化使旧推荐失效，新请求结果不能被旧响应覆盖；
-   草稿支持分组重排、组内和跨组移动、删除、恢复原始推荐；当前候选与待开放活动分别展示，活动条目不参与保存；
-   详情、难度和标签按当前分组和主动展开的同地点分组加载，独立缓存与重试；名称、分类和地图筛选按需建立轻量全局索引，浏览和展示补数不改变后端候选资格；
-   推荐显示后端快照时间、过期提示与同步指引；缺少时间只提示未知，不推断全部未完成。待开放活动从公共标签接口读取名称，开放时间仍以推荐响应为准；排除原因按服务端计数分项展示，不推算去重总数；
-   目标入选以服务端 `role.current_points` 和点数元数据为准，按草稿顺序截取达到目标的最短前缀。只有该前缀内的缺失点数阻止保存；候选已用尽且点数完整时，即使仍有缺口也允许保存，并提示差额；
-   “全部候选 / 只看已入选”和其他浏览筛选不改变保存范围。保存只提交入选 `schema`，并保留服务端版本、阶段、阵营、请求偏好和调整后的分组元数据；保存失败保留草稿。

## 7. 自动检查

第一阶段及后续每阶段至少运行：

```bash
npm run test:achievement
npm run verify:legacy-js
npm run lint
npm run build:dev
git diff --check
```

视图重写完成后，再按 [`../design/achievement-layout.md`](../design/achievement-layout.md) 的视口、语言和数据状态矩阵做浏览器回归。

本轮浏览器专项回归已覆盖 `1280px` 桌面与 `390 × 844` 手机的三个未登录页面，页面宽度均与视口一致；另使用 Chrome 现有登录态验证了真实数据和只读/本地编辑交互。四语言新增键集合由自动契约测试保证一致。
