# 资历宝典维护说明

## 1. 当前目标

普通 Web 资历宝典按“魔盒成就百科”原型重做，只保留三个业务模块：

-   完成进度；
-   亲友对比；
-   渡劫方案。

页面另外提供统一的“资历宝典使用指南”入口。开发环境不要求保留旧 Web 页面代码与旧视觉，后续阶段可以按模块直接替换。

## 2. 路由与范围

| 路由                    | 当前承载                      | 重做目标 |
| ----------------------- | ----------------------------- | -------- |
| `/achievements`         | `src/views/wiki/overview.vue` | 完成进度 |
| `/achievements/compare` | `src/views/wiki/compare.vue`  | 亲友对比 |
| `/achievements/leap`    | `src/views/wiki/leap.vue`     | 渡劫方案 |

`src/views/wiki/index.vue` 是三页共享外壳。旧 `/codex/achievement/*` 页面组件不再保留；如外层站点仍需兼容旧地址，应由站点路由或网关重定向到上述三个新入口。

小程序/App 专用页面仍在 `src/views/wiki/miniprogram/*`，不属于本轮直接重做范围；抽取公共数据逻辑时不得破坏其现有接口语义。

## 3. 新版边界

-   三页统一使用顶部页签，不再使用 `src/components/wiki/sidebar.vue`；
-   Web 布局只按 CSS 断点响应，不再用 User-Agent 决定结构；
-   新版采用暖纸色工作台视觉，旧 `overview-bg.png` 与深色国风背景已经移除；
-   页面使用自然文档流，整页不得依赖固定高度或整体横向滚动；
-   三页共享统一字段协议和接口适配层，业务组件不得直接猜测新旧字段名；
-   接口未提供的未来字段内部保持 `null`，展示时统一为“—”；
-   `0`、`false` 等合法值必须保留，不能按缺失值处理。

## 4. 数据依赖

当前接口继续复用：

-   `src/service/achievement.js`：菜单、点数元数据、角色成就、成就详情、搜索和地图；
-   `src/service/team.js`：本人角色；
-   `src/service/wiki.js`：亲友、亲友角色和渡劫方案；
-   Vuex：当前客户端、角色和成就完成状态；
-   `xlsx`：亲友对比结果导出。

新版统一入口：

-   `src/utils/achievementWorkbench.js`：字段协议、空值规则和纯数据标准化；
-   `src/service/achievementWorkbench.js`：现有接口响应适配；
-   `docs/agents/achievement-workbench-data-contract.md`：字段和替换规则。

## 5. 分阶段实施

### 第一阶段：公共外壳与字段协议（已完成）

-   重做 `index.vue` 公共外壳；
-   移除旧侧栏和入口层的 User-Agent 状态；
-   新增统一顶部页签和指南入口；
-   建立标准成就、角色、目录与角色完成状态适配；
-   接入原型的新字段占位与“—”展示规则；
-   暂时让三个旧业务页继续挂载在新壳内，等待逐页替换。

### 第二阶段：完成进度（已完成）

-   按原型重写总览、稀有度、分类进度、筛选和成就列表；
-   保留现有角色同步和统计口径；
-   接入难度、预计耗时等字段占位；
-   完成加载、未登录、无角色、空数据和失败状态。
-   成就列表按当前页批量读取详情；只有关键词或地图筛选启用时才调用全局搜索接口；
-   `overview.vue` 只保留路由挂载，页面编排集中在 `AchievementProgressPage.vue`，总览、筛选、分类板和列表分别作为展示组件。
-   总览区标题统一为“分类总览”；常规、五甲、隐藏卡片与下方档位下拉联动，点击后留在当前页面并刷新对应成就列表，绝版卡仅展示统计。
-   成就列表提供独立的默认排序和未完成优先排序；“重置”统一恢复常规档位、全部状态、全部地图、默认排序、空关键词和全部分类。

### 第三阶段：亲友对比（已完成）

-   重写角色选择、总览比较、分类短板与对比矩阵；
-   保留亲友添加、移除、筛选组合和 Excel 导出；
-   表格只在内部横向滚动。
-   对比角色最多 4 个，默认载入路由指定角色或本人首个角色；
-   详细分析提供总资历条形对比、前两个角色的四象限交叉统计、最多 4 个角色的资历结构叠加和共同短板分类；
-   关键词/地图搜索复用统一搜索适配器，普通分类浏览仍按当前页批量读取详情；
-   难度和预计耗时继续遵守统一未来字段协议，缺失时展示“—”。

### 第四阶段：渡劫方案（已完成）

-   重写方案列表、创建表单、详情和路线建议；
-   接入成本账本字段和按性价比排序；
-   保留路由查询参数与所有写操作语义。
-   目标资历按“目标值 - 当前资历”计算缺口，只从当前角色未完成、未绝版且资历点数大于 `0` 的成就中生成路线；分类与地图条件可叠加；旧方案详情仍保留绝版或 `0` 点项目；
-   现有综合难度接口继续用于难度上限和低难度优先策略；接口失败时自动降级为高资历优先，不虚构难度；
-   预计分钟、金钱、时间、运气、门派限制和路线备注统一进入成本账本，缺失值显示“—”；依赖缺失字段的策略和排序禁用；
-   新方案的规划条件写入 `meta`，方案成就 ID 继续写入 `schema`；旧方案仍可查看、复制、编辑和删除；
-   路由挂载收敛到 `AchievementLeapPage.vue`，规划器、摘要、路线表、方案列表和保存弹窗使用独立组件；
-   移除旧 `leap/pc.vue`、`mobile.vue`、`form.vue`、`detail.vue` 以及旧 Web 主题文件。

### 第五阶段：清理与专项回归（已完成）

-   移除旧主题文件、路由主题类、旧侧栏/总览组件、旧 Web 总览素材及不再引用的辅助组件；
-   新增 Web 路由、多语言键集合、旧引用清理和小程序独立资源契约检查；
-   新增渡劫方案列表、详情、创建、更新、删除与难度批处理服务契约测试；接口返回空难度时保持 `null`，不再误算为 `0`；
-   小程序/App 的独立页面、`wiki_miniprogram` 数据适配器、`RoleAvatar` 和专用图片资源保持原样，共享旧服务无修改；
-   登录态浏览器已回归真实角色总览、筛选列表、亲友矩阵、添加角色弹窗、方案列表、详情与编辑恢复；未提交或删除云端测试方案，写入语义由服务契约测试覆盖；
-   修复难度下拉 `null` 选项和路线搜索图标造成的运行期告警，最终登录态控制台无警告和错误；
-   亲友导出入口在真实结果下保持可用且执行无控制台错误；客户端 Blob 下载未作为浏览器自动化断言，导出实现仍由 `xlsx` 写文件分支和构建检查保护。

## 6. 必须保护的业务行为

-   正式服/怀旧服 `client` 参数；
-   用户角色、最近角色、角色成就同步与虚拟角色；
-   菜单与点数元数据的统计口径；
-   常规、五甲、隐藏、绝版与特殊成就的分类规则；
-   成就详情、奖励物品和图标链接；
-   亲友关系、亲友角色、多角色对比与导出；
-   渡劫方案的创建、读取、修改、删除和详情恢复；
-   小程序/App 的独立页面和协议。

总览统计公式与特殊 ID 仍以
[资历总览统计业务规则](./achievement-statistics.md) 为唯一基线。

## 7. 自动检查

第一阶段及后续每阶段至少运行：

```bash
npm run test:achievement-workbench
npm run test:achievement-statistics
npm run test:achievement-progress
npm run test:achievement-compare
npm run test:achievement-leap
npm run test:achievement-service
npm run test:achievement-web-contract
npm run verify:legacy-js
npm run lint
npm run build:dev
git diff --check
```

视图重写完成后，再按 [`../design/achievement-layout.md`](../design/achievement-layout.md) 的视口、语言和数据状态矩阵做浏览器回归。

本轮浏览器专项回归已覆盖 `1280px` 桌面与 `390 × 844` 手机的三个未登录页面，页面宽度均与视口一致；另使用 Chrome 现有登录态验证了真实数据和只读/本地编辑交互。四语言新增键集合由自动契约测试保证一致。
