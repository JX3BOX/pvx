## 2. 当前模块范围

资历宝典共用 `src/views/wiki/index.vue` 外壳，主要路由为：

| 路由 | Web 页面 | 专用端页面 |
| --- | --- | --- |
| `/codex/achievement/overview` | `src/views/wiki/overview.vue` | `src/views/wiki/miniprogram/overview.vue` |
| `/codex/achievement/compare` | `src/views/wiki/compare.vue` 统一承载 `compare/pc.vue` 响应式 Web 页面；旧 `compare/mobile.vue` 暂留兼容 | 另有 `miniprogram/compare*` |
| `/codex/achievement/leap` | `src/views/wiki/leap.vue` 统一承载 `leap/pc.vue` 响应式 Web 页面；旧 `leap/mobile.vue` 暂留兼容 | 小程序/App 继续由外层终端能力分流 |
| 目录、列表、对比目录、对比成就 | 无普通 Web 主入口 | `src/views/wiki/miniprogram/*` |

公共业务依赖主要包括：

- `src/service/achievement.js`：菜单、点数、角色成就、成就列表、搜索和地图等接口；
- `src/service/team.js`：用户角色；
- `src/service/wiki.js`：亲友和亲友角色；
- Vuex 中的 `role`、`achievements`、`achievementsVirtual`、`viewAchievementsName` 等状态；
- `@jx3box/jx3box-common` 的角色、图标和成就详情链接能力；
- Element Plus 表格、下拉、级联、弹窗和加载状态；
- `xlsx`：亲友对比导出。

## 3. 改造基线与风险

### 3.1 旧版外壳基线

现代化改造前的 Web 外壳是固定高度的深色全屏画面：

- 主区 `min-width: 1260px`、`height: calc(100vh - 60px)`；
- 内容区固定 `960px`，侧栏固定 `180px`；
- 主区自身横向滚动，页脚仍在文档流中；
- 主区使用 `https://cdn.jx3box.com/design/pvx/overview-bg.png` 与现有深色渐变共同构成资历宝典的国风背景；
- 移动判断依赖 User-Agent，而不是响应式 Web 断点；
- 样式由 `.m-achievement-*` 等宽泛旧类开启，没有现代模块专有根节点。

改造目标是固定宽度、滚动方式、内容层级、响应式和样式隔离。现有国风背景属于资历宝典的核心视觉资产，不属于需要替换的旧样式。

### 3.2 完成进度

`src/views/wiki/overview.vue` 当前约 1300 行，单文件同时承担：

- 登录校验、用户资料和角色加载；
- 角色切换与最近角色记忆；
- 菜单、成就点数和角色完成数据请求；
- 分类树递归聚合、总资历和完成率计算；
- 分类下钻、返回和末级成就表格；
- 桌面与 User-Agent 移动布局；
- 页面绝大部分样式。

主要风险：

- 未登录时先弹确认框，主体因 `currentRole` 为空完全不渲染，用户无法先理解页面用途；
- `getRenderList` 由多个 watcher 和请求阶段触发，改造时容易引入重复计算或异步覆盖；
- 分类下钻依赖 `list_bak`、`name_bak` 和 Vuex 名称状态，返回语义不能只靠视觉重排替换；
- `getCurrentProgress(own, all)` 未单独防护 `all = 0`；
- 页面通过固定高度和内部滚动承载内容，改为自然页面滚动时需要重新处理返回、Sticky 和表格高度；
- 大量界面文案仍为简体中文硬编码，现有 `pages.wiki.*` 路由元信息键也未形成资历宝典完整四语言界面词条。

### 3.3 亲友对比与渡劫方案

亲友对比已经具备较完整业务能力，但仍是独立旧布局：

- 分类菜单、搜索、地图、完成状态筛选、多角色横向表格；
- 自身/亲友角色添加、移除；
- 当前结果导出 Excel；
- 表格宽度按角色数动态扩展。

渡劫方案包含角色切换、方案列表、自定义方案、方案详情和路由查询参数恢复等流程。改造前两页分别维护 PC/Mobile 组件并使用 User-Agent 判断；已将普通 Web 收敛为同一现代响应式页面，旧移动组件不再作为普通手机浏览器入口。

因此“资历宝典”应视为一个多阶段模块工程，不能把总览改造后的局部样式直接覆盖到对比和渡劫。

## 5. 建议目标结构

### 5.1 模块外壳

- `index.vue` 统一使用公共头部、`Nav_v5`、`Main` 和页脚结构；
- 由路由显式开启 `.c-pvx-modern-achievement-*` 根类；
- 现有 `overview-bg.png` 继续作为模块整体背景，不切换为通用 `@pvx-page-bg`；
- Web 页面使用自然文档流，不再依赖整页固定高度和主区横向滚动；
- 左侧国风侧栏可重组为内容内的分段导航或 Sticky 导航卡，但其新版外观必须继续服从背景的国风色调，并保留“完成进度 / 亲友对比 / 渡劫方案”信息架构；
- 小程序/App 专用路由保持独立，不能被 Web 主题选择器误伤。

### 5.2 完成进度页面

建议拆成四层：

1. 页面 Hero：标题、当前角色、总资历、总进度和同步说明；
2. 分类概览：响应式分类卡片，展示完成数、资历点与完成率；
3. 分类面包屑/返回：明确当前层级，不再只依赖侧栏名称变化；
4. 末级成就列表：桌面表格，窄屏改为信息卡或受控局部滚动。

业务逻辑建议先从大文件抽出纯函数或 mixin/composable：

- 分类树递归汇总；
- 完成成就集合标准化；
- 总点数与分类点数计算；
- 进度值归一化；
- 分类下钻路径和返回栈。

只有确认在对比或专用端也稳定复用后，才提升为跨页面公共能力。

### 5.3 登录与角色状态

首屏必须显式区分：

- 未登录；
- 已登录但无绑定角色；
- 角色列表加载中/失败；
- 成就数据加载中/失败；
- 已选择角色且有同步数据；
- 角色存在但未同步或成就为空。

不建议继续以进入页面立即弹确认框作为唯一未登录体验。登录和角色绑定仍使用原入口，不改变权限与接口语义。

## 6. 分阶段实施建议

### 阶段 A：公共外壳与完成进度

- 建立 Web 专有现代根节点和主题文件；
- 在专有根节点中原样承接现有国风背景图片和综合色调；
- 改造模块导航、页面壳和完成进度首屏；
- 保留全部接口、角色同步、分类树和详情跳转；
- 补齐加载、未登录、无角色、空数据和失败状态；
- 完成响应式与四语言界面文案。

### 阶段 B：分类下钻与成就列表

- 使用明确的层级导航替代隐式备份状态；
- 重组末级成就列表，保留奖励 Tooltip、完成状态和新窗口详情；
- 验证大分类、零点数、长名称和异常奖励数据。

### 阶段 C：亲友对比

- 将筛选、搜索、地图和导出整合进统一工具层；
- 保留多角色动态列与横向滚动，但只允许表格容器滚动；
- 重组添加角色弹窗、空角色和无结果状态；
- 验证自身/亲友、角色移除、筛选组合与导出内容。

### 阶段 D：渡劫方案

- 统一方案列表、创建表单和详情结构；
- 保留方案计算、路由查询参数、角色切换与所有写操作；
- 对新增、编辑、删除等有副作用的行为单独回归。

### 阶段 E：专用端复核

- 明确小程序/App 是否纳入视觉改造范围；
- 即使不改造，也要确认 Web 新根节点和公共逻辑抽取没有影响专用端；
- 不使用浏览器宽度模拟专用端路由分流。

## 7. 必须保护的业务行为

- 路由名称、路径、查询参数和现有跳转语义；
- 正式服/怀旧服 `client` 参数；
- 用户角色、最近角色和角色成就同步；
- 菜单与成就点数的统计口径；
- 分类树中数组成就、系列成就和去重逻辑；
- 成就详情外链、奖励物品 Tooltip；
- 亲友关系、亲友角色和多角色对比；
- Excel 导出字段与当前筛选结果；
- 渡劫方案的创建、读取、详情和修改流程；
- 小程序/App 独立页面和原生跳转协议。

必须保护的视觉资产：

- 资历宝典整体 `overview-bg.png`；
- 当前背景的深色渐变、构图方向和国风氛围；
- 分类、资历、头像和侧栏中的业务识别性美术资源。

现代化允许调整这些资产外围的布局、尺寸承载、信息层级和交互反馈，但不得擅自替换或修改资产本身。

## 8. 验收矩阵

### 数据状态

- 未登录、无角色、单角色、多角色；
- 已同步、未同步、空成就、接口失败；
- 总览、一级分类、末级分类、返回；
- 零点数、超长分类名、缺图标、缺奖励；
- 亲友为空、亲友无角色、添加/移除多个角色；
- 渡劫方案为空、有方案、详情和表单。

### 视口

- `1920 × 1080`
- `1440 × 900`
- `1280 × 800`
- `1024 × 700`
- `768 × 1024`
- `390 × 844`
- `320 × 568`

重点检查页面级横向溢出、Sticky 遮挡、表格局部滚动、长文本、弹窗宽度、页脚位置和触控区域。

每个视口还必须单独进行背景回归：

- 背景图片仍清晰可辨且没有被大面积浅色表面遮住；
- 主要构图没有因容器高度、`background-size` 或定位变化出现异常裁切；
- 内容文字与背景对比度足够；
- 半透明表面、边框、阴影和强调色与原背景协调；
- 页面向下延伸时背景衔接自然，不出现突兀的通用浅灰底。

### 语言

- `zh-CN`
- `zh-TW`
- `en-US`
- `vi`

游戏成就名、角色名、服务器名和接口内容保持源文；只翻译前端维护的界面文案。

### 自动检查

npm run lint

git diff --check

总览已有纯数据聚合函数测试：

## 9. 实施原则与阶段结果

推荐先以普通 Web 的 `/overview` 为第一交付单元，同时把 Web 公共外壳设计成能承载后续 `/compare` 与 `/leap` 的结构。视觉上采用奇遇珍卷的“原艺术背景保留、现代外围组件叠加”策略，不迁移成通用浅色页面。第一阶段不应直接改造专用端，也不应一次性重写全部业务逻辑；先通过纯数据层保护和状态拆分稳定统计口径，再进行结构与视觉迁移。

已完成普通 Web `/overview` 第一版：

- 原 `overview-bg.png`、深色渐变、背景构图方向和国风基调保持不变；
- Web 外壳改为自然高度、弹性内容区和响应式顶部/侧边导航；
- 新增深色角色总览、暖米色分类卡片、分类下钻标题和现代成就表格；
- 未登录、无角色、加载失败和重试改为页面内显式状态，不再进入页面立即弹出登录确认框；
- 新增界面文案已覆盖简体中文、繁体中文、英文和越南文；
- 该日亲友对比、渡劫方案和小程序/App 页面尚未改造；普通 Web 的对比与渡劫已在下一阶段完成响应式收敛。

本轮已通过目标文件 ESLint、`npm run verify:legacy-js`、`npm run build:dev` 和 `git diff --check`。浏览器回归覆盖 1280px 桌面与 390px 手机未登录状态，页面无横向溢出且控制台无新增错误或警告；登录态角色切换、分类下钻与成就表格等待用户使用真实账号验收。

## 10. 实施状态

阶段 A 至 D 已在普通 Web 完成首轮落地，小程序/App 专用页面仍保持原业务边界：

- 外壳与背景：三页使用路由专有现代根节点和自然文档流，原国风背景图片、深色渐变与构图保持不变；普通手机浏览器统一渲染响应式 Web 页面，不再按 User-Agent 切回旧移动组件；
- 完成进度：Hero、角色、总资历、分类卡、层级导航和末级成就表格完成现代化；分类进入滚动位置、三级切换、头像/分类图、完成状态、图标比例、奖励加载和物品详情跳转均已专项修正；
- 亲友对比：筛选、地图、搜索、角色与导出合入 Sticky 工具栏；分类可折叠，一级/二级分类在 iPad 分行，成就数量并入表头，总资历固定，表格和工作区按视口控制内部滚动；
- 渡劫方案：方案列表、创建表单、分类/地图三级选择和方案详情已统一视觉；使用说明改为弹窗，空节点与完成成就有明确状态，生成条件受控，删除取消和详情菜单异常已修复；
- 响应式：三页手机端顶部模块导航使用完全相同的宽度、间距、圆角、背景、触控高度和激活态；总览 Hero 在手机端采用标题/头像同排、说明独占行的网格，不再依赖绝对定位挤压文字；
- 国际化：三页非图片界面文案覆盖简中、繁中、英文和越南文，长语言不隐藏业务说明；游戏源数据保持原文；
- 回归：已在当前 `12028` 联调页面检查桌面、iPad 和 `414 × 896` 手机布局，三页无页面级横向溢出；局部表格和分类导航只在自身容器滚动。

后续仍需完成阶段 E 的小程序/App 专用端复核，以及普通 Web 写操作的完整业务回归。当前开发约束是只同步到浏览器正在使用的 `12028` 项目，不另启其他端口；修改对比或渡劫时必须回归已经改造完成的总览页面。

## 11. 总览分类统计口径

总览分类统计的唯一业务基线是 [资历总览统计业务规则](./achievement-statistics.md)。该文档完整定义三个数据源、`point / general / visible` 字段、隐藏开关、总体与分类公式、99 烟花、绝版成就、异常边界、验收数据，并附当前 `general=0/3` 的完整 ID 快照。

维护本页面时只在本文记录模块范围和实施状态，不再复制统计细则；任何口径调整都应先更新业务规则文档，再同步统计实现与自动测试。
