# 红尘侠影业务维护说明

## 1. 文档职责

本文记录 `/pvx/partner/:id` 的数据、路由和状态边界。视觉、动画和各断点布局见
[`../design/partner-layout.md`](../design/partner-layout.md)，公共组件接入规则见
[`../agents/public-components-integration.md`](../agents/public-components-integration.md)。

## 2. 页面组成

| 文件 | 职责 |
| --- | --- |
| `src/views/partner/Index.vue` | 路由、列表和详情请求、当前侠客、Tab 状态及页面外壳 |
| `Selector.vue` | 侠客搜索、客户端过滤、选择与横向/纵向列表展示 |
| `Portrait.vue` | 背景和人物图片自然尺寸读取、加载失败状态及切换显示 |
| `Info.vue` / `SkillList.vue` | 结识方式、技能、境界和属性展示 |
| `Bio.vue` | 传记与语音手风琴 |
| `InfoTabs.vue` | 基础信息与传记的互斥切换 |
| `src/service/partner.js` | 侠客列表、详情和技能详情接口 |
| `src/utils/partner.js` | 接口字段映射和技能图标解析 |

## 3. 路由与选择

- 直接访问数字 ID 路由时，以路由参数作为当前侠客并请求详情。
- 点击人物先把 Tab 重置为“基础信息”，再更新详情路由；目标 ID 与当前路由相同时直接刷新详情，避免重复导航错误。
- 列表接口中的“全部”占位项不进入人物选择器；没有路由 ID 时默认选择第一位真实侠客。
- 搜索防抖由 `Selector` 负责，页面只接收最终关键词并重新请求列表。

## 4. 请求并发与加载状态

- 列表/搜索和详情分别维护 `searchRequestId`、`detailRequestId`，两类请求互不覆盖。
- 每次发起请求先递增对应序号；响应、异常和 `finally` 只有在序号仍为最新时才能写入页面状态。
- 快速搜索、切换人物或路由变化时，旧响应不得覆盖新列表、新详情，也不得提前关闭最新请求的加载状态。
- 技能详情属于当前侠客详情请求的一部分；合并技能数据前后都要校验 `detailRequestId`。
- 技能接口兼容按 ID 索引的对象和带 `SkillID` 的数组两种响应结构，数组顺序不能作为技能对应关系。
- 技能详情请求失败时保留侠客详情中的基础技能数据，不因附加接口失败清空整页。

## 5. 展示状态

- “基础信息 / 传记”只允许一个激活态。
- 切换侠客后默认回到基础信息。
- 传记使用手风琴模式：有传记时默认展开第一项；没有传记但有语音时默认展开语音；两者都没有时不展开。
- 技能类型是技能的分类信息，以右侧 Tag 展示；技能名称和描述仍使用接口源数据。
- 背景或人物图片加载失败时分别进入自身失败状态，不能影响另一张图片或资料内容。

## 6. 国际化边界

- 搜索占位、Tab、错误反馈、QQ 提示、空立绘、技能类型及固定栏目名称由 `pages.partner` 维护，简中、繁中、英文和越南文结构保持一致。
- 侠客名、技能名、传记、语音、地图和接口说明为游戏源数据，不在页面层猜测翻译。

## 7. 最低回归

- 直接访问任意有效 ID、点击人物和点击当前人物均能得到正确详情；
- 快速连续搜索或切换人物时，最终列表、详情和加载状态对应最后一次操作；
- 技能对象/数组两种响应格式都能按 ID 正确合并；
- 技能附加请求失败时基础详情仍可阅读；
- 信息与传记 Tab 互斥，切换侠客后恢复基础信息；
- 传记一次只展开一项，默认项符合数据情况；
- 四语言固定 UI 不缺键，长文本不改变路由或请求参数。
